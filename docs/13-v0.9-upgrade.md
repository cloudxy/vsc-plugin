# v0.9：从流程声明走向可验证的结果与学习

本次升级依据哲学、架构、专业制作与持续学习四维审查。保留独立插件和模块化单体，不嵌套其他插件；新增实现不冒充真实模型生成或专业审美能力。

## 审查问题与实现

| 问题 | v0.9 实现 | 边界 |
| --- | --- | --- |
| 创作目的停留在说明 | 创作委托契约记录观众、体验、目标顺序、成功证据、底线与冲突裁决 | 目标由负责人确认，不自动优化成单一分数 |
| 空文件或错阶段也能交付 | 产物类型绑定契约；批准、Gate、上下文共用版本检查 | 结构与文件有效不证明故事好看 |
| 批准后文件变了仍可用 | 登记保存内容快照与完整 SHA256；快照变化或消失即失效 | 工作文件变更不改变既有版本，需登记新版本 |
| 上游改变未影响下游 | 保存依赖版本并递归检查；明确替代或拒绝使旧链路失效 | 自定义 explicit Profile 无法检测漏声明依赖 |
| 并行写入丢数据 | 本机 CLI 在读状态前加锁；revision 拒绝已过期写入 | 不是多机分布式事务，禁止其他工具直接改状态 |
| 历史规则被当前 Profile 覆盖 | 完整 Profile 内容与摘要固定到项目 | 不冻结整个插件代码、模型和依赖环境 |
| 镜头或资产引用可以不存在 | 创作对象注册、父级类型、资产版本绑定与跨文件检查 | 不自动识别真实画面中的人物或姿态 |
| 一份剧本代替多集完成 | 连续短剧从 script 起逐 episode 验收 | 其他业务范围可由 Profile 定制 |
| 试用方法没有派单入口 | 显式 pilot 上下文与 trial 记录 | 不自动调用模型或花费预算 |
| 一次 pass 掩盖后续 fail | 比较基线、输出与报告绑定；未解决 fail 阻断晋升 | 判据与结果仍由负责人判断 |
| 记忆越积越大 | 按任务词汇／领域相关性和字符预算检索 | 尚非语义向量检索、自动遗忘或矛盾融合 |
| 项目经验无法迁移 | 只导出去项目化方法，导入 draft 重新评测 | 自然语言去项目化须人工复核 |
| 上游只改规则文件未被发现 | Skill 资源包变化、完整性与可重试分析 | 外部网站内容、动态依赖不在资源包中 |
| 专业制作只有计划 | 真实 ffprobe QA、裁切／声画参数、人工审片并接入 delivery | 未完成 AI 样片或 Remotion 实际渲染验收 |

## 创作目标落入运行流程

`init` 生成 `00-委托/创作委托.json`。按 `templates/creative-brief.json` 填写实际选择；目标数组顺序表示优先级，`success_evidence` 描述怎样观察结果，`conflict_policy` 说明冲突时由谁如何决定。模板占位项不能批准。

例如某项目把“人物因果清楚”放在“时长更短”前面：为了压缩时长而删掉动机时，应提交创作决策，说明收益、损失和备选。技术检查不能替负责人宣称该删减合理。

## 版本、依赖与范围

产物有两个不同路径：`source_path` 是工作文件，`path` 是登记时保存的版本。下游只消费版本路径与完整摘要。即使工作文件被修改或删除，原批准版本仍可用；批准快照本身变化、删除、被替代或依赖失效则不能使用。

默认 Profile 为 1.1，`dependency_policy: previous_stage` 要求必需产物显式依赖前一阶段的全部基线。省略依赖不能批准；若上游被拒绝或明确替代，下游必须重新检查与返工。自定义 Profile 可以使用 `explicit`，但需承担漏声明的风险。

下面是已有批准前置产物之后的登记示例；编号需换为本项目实际输出：

```bash
python3 scripts/vsc_state.py object add ./project --kind episode --id EP-001
python3 scripts/vsc_state.py object add ./project --kind scene --id SC-001 --parent EP-001
python3 scripts/vsc_state.py object add ./project --kind sequence --id SEQ-001 --parent SC-001
python3 scripts/vsc_state.py object add ./project --kind shot --id SH-001 --parent SEQ-001

# A-0005 / A-0006 为已批准改编与分集节拍基线，不是任意占位编号
python3 scripts/vsc_state.py artifact add ./project --type vsc.screenplay --stage script \
  --scope EP-001 --file ./ep01-v1.md --depends A-0005 --depends A-0006

# 已批准 A-0007 需要返工时，登记新的内容；批准后旧链路不再有效
python3 scripts/vsc_state.py artifact add ./project --type vsc.screenplay --stage script \
  --scope EP-001 --file ./ep01-v2.md --depends A-0005 --depends A-0006 --supersedes A-0007
```

集、场、sequence、镜头、take、资产使用不同的唯一 ID；已登记身份不能重新解释。scene 归 episode，sequence 归 scene，shot 归 sequence，take 归 shot。asset 与 take 必须绑定有效已批准产物。资产可以在多集引用，但其具体批准版本必须仍有效。

当前 sequence 表示一个场内镜头组，出入点 scene_id 必须与其父场一致；跨场由时间线组合多个 sequence，不允许把另一个已登记场景静默冒充本场。跨场桥接的完整自动检查仍需后续扩展。

`vsc.adaptation_plan`、`vsc.shot_plan`、`vsc.sound_plan` 分别采用改编映射、连续性计划和声音 Cue 契约；模板中的 `project_id` 要替换为 `vsc.json` 的真实项目 ID，不是标题。所有集必须有可拍场景单元。

```bash
python3 scripts/vsc_state.py continuity validate ./continuity.json --project ./project --scope EP-001
python3 scripts/vsc_state.py sound validate ./sound.json --project ./project --scope EP-001
```

独立 `vsc_kernel.py contract validate` 检查结构；批准和 Gate 自动增加项目引用、范围、版本及依赖检查。默认连续短剧 Gate 不接受一份 project 级 screenplay 证明全部分集完成。

## 如何把使用反馈变为能力

先记录来源与正／负观察，再提炼带适用条件的方法。pilot 只有通过显式任务调用才进入派单；普通上下文不会自动使用未批准能力。

```bash
python3 scripts/vsc_state.py context build ./project --role director \
  --task "比较五拍方法对打斗方向与情绪衔接的帮助" --artifact A-0007 --pilot C-0001

# 输出 A-0009 依赖试用输入；报告 A-0010 依赖基线 A-0008 与输出 A-0009
python3 scripts/vsc_state.py capability evaluate ./project C-0001 \
  --context CT-0001 --output A-0009 --baseline A-0008 --evidence A-0010 \
  --criteria "同输入下，动作方向清楚且情绪反应不弱于原方案" \
  --result pass --by "导演" --note "记录具体镜头/时间码及比较结果"
```

基线与输出必须同类型、同范围。评测记录方法摘要、上下文版本、输入、输出、基线、报告和判据。先 pass 后 fail 仍有未解决反例，不能晋升；明确可比重测可用 `--resolves EV-ID`，原失败记录保留。单次 pass 是最低程序条件，不等于专业泛化或长期提升。

检索按任务词汇／领域重合排序，并限制知识字符预算。可以显式 `--memory`、`--capability` 选择，但不能绕过可见性、有效性和预算。任务／父摘要各最多 6000 字符；最多 50 个输入、输入元数据最多 20000 字符；任务包最多 150000 字符。父摘要会保存在上下文文件，不进入长期状态，也没有自动删除承诺。

跨项目用 `capability export/import`，只输出人工重新填写的通用名称、方法、限制、角色与标签。方法包不包含项目事实、来源、观察、记忆、试用或评测；自然语言本身是否已经去项目化，仍由导出者负责。导入 draft 后在新项目重新复核、试用和评测。

进一步的“聪明”需要持续衡量合格素材比例、连续性错误、返工、成本和观众理解；目前没有自动观众实验、自动目标修正、权重训练或跨项目自动批准。

## 专业制作与交付

交付 Gate 增加 `vsc.sample_review`。先准备真实媒体与 Remotion 计划，生成真实成片技术报告，再具名审查剧情、物理／情绪连续性、剪辑覆盖、对白／音乐以及实际耗时、成本和失败。

`vsc.media_qa` 可在 post 阶段登记；`vsc.sample_review` 在 delivery 登记并依赖 post 基线及技术报告。审片文件使用同目录相对 `technical_report` 时，登记会一起保存该报告；不能以 `../` 越出目录。绝对报告路径保持 hash 绑定。媒体与计划仍需保持可访问，搬迁／修改后重建技术证据。

技术报告的 `plan_sha256` 必须等于所依赖的批准 timeline／render-plan 版本，审片依赖的技术报告摘要也必须一致。建议对已登记计划的快照路径执行 QA，而不是对会继续编辑的工作文件执行；普通说明文件不能替代该确切计划版本。

默认连续短剧按每集 scope 登记审片，绑定计划中的 source_shot 必须属于该范围。不能把只检查源素材、模拟故障或空报告当作真实成片证据。技术检查会重新运行本机 ffprobe，因此机器需要 FFmpeg；缺工具明确失败，不假通过。详见 [专业制作证据链](14-production-evidence.md)。

## 旧项目迁移

```bash
python3 scripts/vsc_state.py migrate ./project
```

原 `vsc.json` 会完整备份到 `09-台账/vsc-schema-N-*.json`。旧批准产物降 draft 并标记未验证，旧能力降 draft、旧评测保留为历史；需要重新登记产物版本与重新评测。来源权属不会凭迁移自动变为 owned。

历史 Profile 版本与当前版本不一致且无法恢复时，默认停止。负责人确实选择用当前规则继续，才运行：

```bash
python3 scripts/vsc_state.py migrate ./project --accept-current-profile
```

这是显式接受新规则，不是恢复了缺失的历史规则。不要删除旧工作文件或状态备份。若要回退，由负责人选择对应备份并恢复，不做自动覆盖。

## 运行与权限边界

所有本机项目命令在读状态前持有同一文件锁；写入有 revision 校验及原子替换。其他工具只能调用 CLI，不应直接改 `vsc.json`。当前采用 macOS/Linux 的 `fcntl`，不宣称支持 Windows 或多机共同写入。

`--by` 是审计标签，不是登录身份验证。角色 authority、人工批准和文件状态不是一个认证授权系统；宿主负责执行权限。真实生成适配器、队列、模型训练和发布不在本次实现中。

Vendor 维护实现已移入项目，现通过手动脚本按需执行；完整资源包、可重试分析、删除处理与旧中央入口兼容见 [候选更新说明](12-vendor-candidate-updates.md)。不会在升级时自动采用上游 Skill 或改变路由。
