# 创作工作台

首页按画布、视频、分镜和文字工具直接进入创作。“我的项目”集中显示项目、画布和媒资；新建项目可选择连续短剧或单条短视频。工作区维护从首页底部进入。连续剧按集制作、共享人物和场景；单条短视频默认使用轻量流程。维护入口用于 VSC 配置、执行器和服务问题。新制作入口使用现有 PostgreSQL 项目；旧 JSON/SQLite 项目继续沿原权威读取，须明确迁移后才能使用数据库制作功能。

营销工作室的案例视频、案例封面与技能封面使用本地原文件。预览可拖动播放；文件缺失或校验失败时显示资源不可用。

## 项目归属、协作与分享

每个项目都属于用户或团队。项目页分为“个人项目”“参与项目”“团队项目”：本人所有的个人项目、受邀参与他人的个人项目、可访问的团队项目，三类互不重复。画布库和媒资库沿用所选分类。项目卡只显示名称、日期和类型，不展示归属人或创建者。账号注销不会清空项目归属。

新建项目默认归本人；创建表单可明确选择有编辑权限的团队。团队管理页选择团队只影响该管理页，不改变后续项目的创建归属。项目内的“转移项目”先显示权限变化、保留的直接授权和有效分享链接，再确认转移。

账户菜单用于个人设置，顶部“团队管理”用于团队及其成员。项目内邀请协作者只授权该项目，不将对方加入整个人的项目范围。移除团队成员时先查看保留的项目直接权限，可明确同时收回；团队项目不因创建者退出而变成个人项目。

在画布内打开“分享”：固定版本预览保持所选内容，实时画布协作包括后续变化；链接不授予生成或批准权限。项目成员协作开关只控制项目成员，编辑分享链接在分享页独立撤销。收到分享后通过原链接访问，无需将其作为自己的项目或团队。

## 从项目到可播放首版

打开项目，建立或选择一集，直接进入分镜、视频或 Agent 工作流。制作页顶部可切换项目、分集及画布、分镜、视频、Agent 和资产；当前输入随原集保留。首次没有镜头时，可在分镜页新增场景、镜组与镜头；参考图片可在当前页上传登记。需要查看批次、缺项和正式交付时，打开本集“制作进度”。完整专业工具保留在本集页面，不要求为了做一条视频逐个打开。

```mermaid
flowchart LR
    A[创意或小说] --> B[分集剧本与制作方案]
    B --> C[汇总本批人物、场景、道具与声音需求]
    C --> D[引用公共资产与固定形态]
    D --> E[就绪镜头并行制作]
    E --> F[画面、声音、字幕合成首版]
    F --> G[集中审看与局部修补]
    G --> H[正式时间线与交付]
    E --> I[有依赖的镜头等待所用结果]
    I --> E
```

先固定全剧的身份与基本设定，实际生成按当前批次准备。后续集尚未使用的资产不阻塞本集；同一人物的不同服装、状态或场景角度引用各自固定形态。替换资产前查看所影响的镜头，既有固定版本不会自动被覆盖。

镜头输入齐备后，在当前卡片查看真实模型参数、用量和报价，点击生成即可进入原任务。上传参考和当前工作选取可以直接用于本次制作；保存工作稿、生成候选与正式采用分别记录。恢复原批次保留已经发生的尝试、截止时间和预算；确实需要新一轮抽样时，明确选择新授权批次并说明理由。商业计量启用时，另行选择承担账户。任务页显示已受理、在途、待对账、失败与已有结果；未知提交应先恢复原任务，不能当作失败反复点击重发。

镜头完成后先形成可播放首版。字幕、音量、裁剪或接点问题在剪辑中修改，只对需要更换画面的镜头重新生成。普通建议不自动开启新一轮制作。完整首版与部分镜头预览分别标识，后续真实作品审片才能判断速度和专业效果。

在剧本页选择“继续制作”时先保存当前输入，再进入本集 Agent；已保存的角色与服装、场景角度等形态可直接复用原图。Agent 的镜头条件包括叙事目的、入出状态、衔接和声音路线，随工作生成稿保留。选择多个视频镜头后核对整批报价，可一次提交就绪镜头；缺参考或未映射的镜头单独显示，不阻塞其他就绪镜头。回到原批次即可查看任务及缺口，本集任务中心只显示当前集相关任务。

提交时可选“候选齐备后自动组装首版”，并设置首版目标、停止新增提交时间和尝试上限。实际成功视频被选中且整集素材齐备后，系统保存原剪辑稿并排队本地合成；有人工改稿则保留修改。首版目标已到仍缺素材时会保留一次缺口回执，补齐后继续。声音 Cue 使用已固定音轨与区间，字幕只采用绑定原台词和音频的实测时码；未审阅项在剪辑与回执中展示。

## 选择制作入口

| 任务 | 入口与结果 |
| --- | --- |
| 直接制作某一镜 | 经典制作按集、镜头与模式保存独立草稿；引用、参数、报价和输出都回到原镜头 |
| 按整集剧本推进 | 智能创作、智能分镜保存阶段和模板版本；资产提取可编辑后导入原资产与需求，二维派生站位只等待其实际锚图 |
| 自由组合素材与任务 | 创作画布保存节点、连线、布局与历史，刷新回到当前画布。Agent 可逐项确认，也可一次明确启用限定模型、任务数、时长、费用和截止时间的自动媒体范围 |
| 布置空间与机位 | 站位设计、空间预演保存场景、机位和时间；对话可直接保存可编辑新版本，也可先审计划。截图、GLB 或视频输出可回流制作 |
| 配音、配乐与加工 | 音乐与视频工具保存声音范围和原音选择；本机裁剪、声音提取或混合保留源素材和输出记录 |
| 小说、翻译、评分、拉片、质检、出海 | 剧本与分析工具保留各阶段版本、逐项任务和导出；结果导入剧本或剪辑前显示目标与变化 |

界面显示的模式不等于当前账号具备执行能力。模型参数按已配置适配器校验；缺少执行器的工具保留草稿并说明缺项，不生成占位成功结果。三维预演支持内嵌 PNG/JPEG 纹理、核心材质、骨骼蒙皮和动画采样；模型继续引用原素材，不复制进每次场景保存。GLB 可导出所选时刻的静态场景或保留所选时间段的动画；PNG/视频使用同一场景与机位。单文件上限 20 MiB，场景累计 12000 顶点、24000 三角面、4 Mi 纹理像素；外链和未支持扩展会拒绝。

原生工具包括独立蒙版重绘、全景及环视、4K/8K 超分、深度视频与后继动作生成、歌词演唱，以及原 480p 视频任务升级 1080p。数字人先选择讲话主体，再固定音轨和表演说明；可显式识别主体或手绘蒙版。各项须配置相应供应商与账户权限；识别、原片和后继任务分别保留用量与结果。

经典制作中的图像编辑保留原图，可使用画笔、矩形、箭头、文字、橡皮、遮罩和取色，支持撤销重做；视频标注同时固定源视频与时码。编辑后的图片必须明确加入参考，清除引用不会删除源媒体。宫格裁剪得到独立图片结果，高级生成加工仍需对应适配器。

首页的独立文字工具、独立音乐与视频工具都可在未选择作品时打开。个人工具范围按当前身份保存，重入可继续；完成本机加工后，明确选择目标作品和一集，将固定输出导入剪辑工作稿。同一输出用于同一作品的多集时共用素材，源稿和源文件保留。导入不自动确认权利、选片或批准。

## 剪辑、下载与正式交接

剪辑工作区可加入同一素材的多个片段，分别裁剪、重排、分割，并调整对白、BGM、环境声、音效和字幕。修改帧率会换算入出点与字幕时码，尽量保持实际时长。保存与合成使用固定版本；离开页面或断线后，可恢复尚未收到响应的操作，避免重复建立相同版本。

工作稿支持 MP4、SRT、当前画面封面、选中片段与包含源片的 ZIP 工程；播放器同步声音、字幕和裁剪，画面可设置淡入淡出及相邻淡黑。下载的是已保存版本；继续编辑的内容需要先保存。工程内含固定剪辑、输入映射、校验值和本机渲染入口，需在具备 VSC 与 FFmpeg 的环境运行。它与最终交付件分别记录。

“交接正式时间线”要求逐片段选择原选片项和采用决定；可听声音同时绑定原声音计划及 Cue。预览后创建待审时间线，经原审阅入口批准，再冻结。工作稿的保存、预览或下载都不会代替正式选片、批准和交付检查。

## 素材、协作与服务

批量导入按文件保留进度与回执，支持继续未完成上传。任务中心可定位到原导入批次、文字工具、画布、空间导出或剪辑记录。文字批次显示成功、失败、受阻与待处理子项；顶栏通知按当前成员和项目保存未读状态，可定位较早任务，恢复仍操作原任务。资产中心默认浏览真实媒体，规格目录、下载历史与个人清单另有入口；可将固定素材直接添加到目标项目，或用图片建立参考画布。

项目资产页可编辑公共人物、场景、道具、声音和各自形态；分集别名与当前形态引用独立保存，多集共用原媒体。资产复制明确选择目标项目，保留原来源和用途限制。

团队角色分别控制编辑、审阅、批准、执行和管理。分享链接固定范围与版本；可编辑分享沿同一画布编辑节点布局、文字和连线，冲突时保留本机稿，撤销后旧链接不能继续操作；API 凭据与网页登录凭据分开，权限同时受项目成员身份限制。

顶栏“账户”进入登录与身份设置。邮箱、手机验证码和 OIDC 通道按部署配置启用，绑定当前账号需要明确操作，不自动合并身份；本机管理凭据仍从设置进入。界面可切换 27 种语言，当前输入和创作内容保持原样；非中英文的专用说明会明确回退英文。

项目管理支持文件夹归类、改名、回收与恢复。回收对象退出新的制作任务；固定历史资料保留，恢复沿原身份继续。永久停用会检查引用和在途任务，保留审计；当前不自动物理删除文件，也不据此报告释放了磁盘空间。

API 密钥可设置来源 IP/CIDR 和每分钟调用上限。来源按服务实际连接地址判断，不信任客户端自行填写的转发头。本地账户停用先显示需要转交的归属及未处理账目，确认后撤销凭据；作品与审计记录仍保留。

首页的独立文字工具无需先建立影视项目，使用自己的工作区保存小说、译文与评分稿。完成后选择目标项目，预览并导入固定文字版本；来源保留，目标形成独立稿，原项目内的精校和风格引用需在目标重新选择。含视频引用的工具须先显式导入媒体，不能直接套用其他项目的媒体编号。

商业功能需要明确配置当前套餐、模型计量、账户、额度和服务接口。支付、开票、短信或外部分发未接通时，页面保留申请与恢复状态，不显示外部业务已完成。套餐的下载水印会应用到 MP4、封面、选中片段及工程包，源媒体和在线预览保留原内容。当前退款支持整笔未使用订单，续期为显式手动另购；不承诺部分退款或自动续扣。

## 关系查阅

“场镜工作台”和关系画布继续是只读查询入口。浏览、检索、分页和关系布局不修改项目版本，也不产生素材选择或批准。旧项目缺少索引时返回明确缺口，不自动迁移或猜测文件名。

## 查询

关系查阅按“当前任务 → 资料分组 → 具体内容”组织，仅显示当前分组的子项；统计数量随内容集合展示。分组与具体内容分别标记选中状态，键盘切换及读取完成后保留焦点。

| 当前任务 | 资料分组 |
| --- | --- |
| 场镜工作台 | 创作概览、剧本与镜头、资产与表演、制作执行、质量与方法 |
| 生成候选 | 候选与素材、任务与尝试、质量与方法 |
| 剪辑交付 | 剪辑用料、交付文案、质量与方法 |

各任务分别记住自己的资料选择。首次进入生成候选显示“采用与候选”，首次进入剪辑交付显示“实际用料区间”；切换范围后保留该任务的选择。项目概览按需显示结构分组和资料集合，进入场或镜头后可以查阅剧本、资产、使用状态、声音、动作与特效、用途候选及固定版本。镜头覆盖、声音覆盖、参与者和制作参考可按关联继续查阅；候选可以加入已有并排比较入口。

检索可以限定当前范围，也可以选择全项目；状态、类型、用途和关联情况分别筛选。“当前文案”与“已批准”含义不同，历史批准保留。场镜状态和人物声线有独立入口。未登记关系和旧项目未索引资料会显示缺口，不能据此判断没有依赖。

无限画布提供创作关联、制作来源、采用用料和版本影响视图。全部项目先展示分组，点选范围再展开；“全范围检索”可定位尚未加载的素材。影响报告列出直接和间接消费者，标记原版本后可以比较替换影响，查阅操作不改变正式选择。预览使用已登记的缩略图、海报和波形，原始媒体按明确打开动作加载。

HTTP：`GET /api/v1/projects/{project_id}/workbench`（沿面板既有鉴权与项目路由）。参数：`object_id`、`section`、`query`、`kind`、`status`、`purpose`、`version`、`association`、`entity_id`、`limit`（1–100）、`offset`、`revision`。全项目无筛选概览只取聚合与子级，集合用 `load_on_demand` 标记；场镜 `overview` 每类最多六项，单独集合可继续分页。

CLI 使用同一应用接口：

```sh
python3 -B scripts/assets/workbench.py PROJECT_ID --object-id SHOT_ID --section overview
python3 -B scripts/assets/workbench.py PROJECT_ID --section materials --query 杯子 --limit 24
python3 -B scripts/assets/workbench.py PROJECT_ID --section cue_shots --entity-id CUE_ID
```

`VSC_DATABASE_URL` 未加载时仍可读旧项目；声明 PG 权威的项目拒绝回退。命令不显示连接信息。返回 `scope`、`ancestors`、`summary`、`sections`、`gaps`、`warnings`。每个集合区分 `scope_total`、`filtered_total`、`loaded_count`，并给出 `next_offset`、`truncated`。PG 查询使用一次只读 repeatable-read 快照；传入过期 revision 返回冲突，调用方应重新刷新。

集合包括 `children/shots/lines/assets/instances/cues/performances/bindings/candidates/materials/versions`，以及有界关系明细 `coverage/states/voices/interactions/dispositions/cue_shots/cue_slots/cue_timeline_items/timeline_media/execution_shots/execution_participants/execution_materials/execution_slots`。`jobs/quality_observations/method_evaluations`提供任务、待审输出计数与固定质量证据。`entity_id`可定位行、资产、槽位、执行或 Cue，`version`可指定固定产物 ID；`current`/`version_status`区分当前、历史批准与草稿。实例的 `use_count`指已登记使用，不推断遗漏资料。

画布节点 ID 使用 `line:UUID/state:UUID/voice:UUID/instance:UUID/cue:UUID/performance:UUID`。`mode=creative/production/usage/impact`切换关系视图。impact 只沿固定任务输入、加工、实际采用与成片用料传播，返回直接/间接距离与理由；`affected_pending_review`表示需要复核，不等于必须重生。截断、未登记依赖、未比较替换内容的部分均无法判定，不自动标成“不受影响”。

## 登记和权威

新增关系文档固定格式 `vsc.creative-relations/v1`，通过现有 `create_artifact` 登记，`artifact_type`固定为 `creative-relations`。服务在同一项目 revision 事务内保存正文 SHA 和 typed 投影，投影不可直接更新/删除。外部剧本行、规格、状态、方法和时间线引用必须在 `dependency_ids` 中固定其所属产物版本；项目内复合外键阻止串项目。方法批准仍不等于能力已获验证。

```json
{
  "artifact_key": "scene-uses",
  "artifact_type": "creative-relations",
  "object_ids": ["SCENE_UUID"],
  "dependency_ids": [],
  "document": {
    "format": "vsc.creative-relations/v1",
    "project_id": "PROJECT_UUID",
    "instances": [
      {"key": "cup-left", "asset_id": "CUP_ASSET_UUID", "scene_id": "SCENE_UUID", "shot_id": "SHOT_UUID", "label": "左侧杯子", "state": {"position": "桌左", "orientation": "杯口朝上", "damage": "完好", "consumption": "未消耗"}},
      {"key": "cup-right", "asset_id": "CUP_ASSET_UUID", "scene_id": "SCENE_UUID", "shot_id": "SHOT_UUID", "label": "右侧杯子", "state": {"position": "桌右"}}
    ],
    "interactions": [{"subject": "cup-left", "object": "cup-right", "relation": "touches"}],
    "cues": [{"key": "pause", "kind": "silence", "label": "有意停顿", "scope_object_id": "SCENE_UUID", "shots": [{"shot_id": "SHOT_UUID", "start_ms": 1000, "end_ms": 1800}], "parameters": {"purpose": "留出反应"}}]
  }
}
```

以上 UUID 是字段占位，须替换为该项目真实登记 ID；不是可直接导入的作品资料。实例 key 在该不可变文档内唯一；同一资产可有多个实例。状态 JSON 保存摆放、朝向、损坏等参数，参与对象引用放正式字段。`interactions` 的双方引用本文实例 key 或已登记实例 UUID，`holds` 另记 `hand`；`restores/consumes`记录恢复/消耗关系。`dispositions`引用固定 `line_id`、`disposition=omit|defer`和理由；只有其版本经既有批准路径批准后，才显示为当前明确决定。

保存为 payload.json 后沿既有写入口登记：

```sh
python3 -B scripts/assets/resources.py apply PROJECT_ID create_artifact \
  --payload payload.json --expected-revision REVISION --key UNIQUE_COMMAND_KEY --by ACTOR
```

登记得到固定 artifact ID 和 SHA 后，按现有审阅决定调用 `decide_artifact`。不得替用户批准或把自评写成人审。版本修改登记新文档，不覆盖历史投影；用途素材仍由 propose/review/select 路径采用。

## 表粒度和专业执行

| 表 | 一行含义与候选键 |
| --- | --- |
| asset_use_instances | 固定文档内一次可区分的场镜使用；project + artifact + instance_key |
| instance_interactions | 两个使用实例的一次有类型交互；project + id |
| script_line_dispositions | 固定关系版本对一条固定剧本行的省略/延期提案；project + artifact + line |
| execution_instances | 一次专业或普通动作执行规格；project + artifact + execution_key |
| execution_shots | 执行到镜头的覆盖；project + execution + shot |
| execution_participants | 执行参与实例及角色；project + execution + instance + role |
| execution_materials / execution_slots | 执行的参考素材/用途槽位及角色；project + execution + media/slot + role |
| sound_cues | 一次声音意图，包含有意静默；project + artifact + cue_key |
| cue_shots | 一个 Cue 覆盖一镜及可选镜内毫秒范围；project + cue + shot |
| cue_slots / cue_timeline_items | Cue 对用途/实际时间线条目的 M:N 关系；project + cue + slot/item |
| quality_observations | 固定文档记录的一次任务/输出观察；project + id |
| method_evaluations | 固定方法、试片、基线/输出、判据和环境的评测；project + id |

一个跨三镜的环境声 Cue 只登记一次，`shots`列三镜，`timeline_item_ids`可指向一个跨镜用料。源区间、目标帧、混音包络继续由既有时间线保存；Cue 的镜内毫秒不能替代源区间或成片帧坐标。Cue 可用 `subtitle_version_id/lipsync_version_id` 固定字幕/口型同步规格，须列入文档版本依赖；这是同步依据，不冒充已完成同步检验。原生音画一体及声音抽取继续通过原媒体/加工输入输出追溯，不伪造独立录音。

`performances`每行含 `key/label/domain/method_artifact_id/shot_ids/participants/materials/slots/parameters`，可带固定 `line_id/voice_spec_id`。domain 支持 `combat/dance/vfx/voice/acting/action`。四专业领域经 `vsc.production.performance.execution_problems` 检查可观察参数，方法须已批准且固定为依赖；打斗参与双方、舞蹈音乐、特效施放/目标及所需层、声音台词/声线都必须是 typed 引用。参数不接受 `*_id/*_ids/*_ref/*_refs`对象引用。制作上下文消费当前批准执行规格；实际供应商能力仍由生产检查核对，登记本身不承诺生成成功。

关系未登记、旧格式未索引、权限不可用和数据截断分别显示，不能仅凭某页为空判定“没有依赖”。合成性能测试只证明工程规模；真实制作质量、真实项目负载和浏览器交互必须另行验收。

## 局部制作

镜头卡的“只重做本镜声音”、实例卡的“替换这个实例版本”和任务卡的“新增一次抽样”先加载本项目实际候选，显示固定目标、版本及参数差异。确认预览只建立待审产物；阅读固定正文后批准，运行包才可入队，生成worker仍须显式执行。未知或在途原任务先恢复，不作为重提入口。实例换规格只改变所选实例，保留同一资产身份与其他实例；库版本更新不会改写已固定项目输入。

CLI及AI复用`resources.py local-preview PROJECT_ID --payload FILE`，再经`apply ... propose_local_production`和已批准后的`enqueue_local_production`。服务会在事务内重建预览摘要、核对当前版本及正式契约；页面上的影响清单不是自动重生或批准决定。
