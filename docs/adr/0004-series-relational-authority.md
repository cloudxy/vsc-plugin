# ADR 0004：连续短剧的关系库权威与镜头上下文

- 状态：已采纳，v0.13.0；适用于新建或显式迁移至 `vsc.series-db` 的项目。
- 依据：[60 集以上工作流升级方案](../plans/2026-10-13-serial-drama-workflow-upgrade.md)与 [drama-skills 对标](../plans/2026-10-13-drama-skills-benchmark.md)。

60 集以上、每集约 3 分钟的制作需要跨集追踪剧本、人物、地点、声音、镜头、候选和选择。原 `vsc.json` 足以表达状态，但不适合让 AI 按关系检索大量固定版本。采用新的 Profile，保持 production-v2 的阶段、依赖、批准与交付 Gate，同时将项目状态的唯一写入权威改为 `.vsc-series.sqlite3`。`vsc.json` 是旧只读消费者的派生镜像；摘要不一致时阻断操作，`repair-mirror` 只从数据库恢复镜像。旧 Profile 继续以 JSON 为权威，不能静默切换。

批准产物和短文本来源在数据库中有关系索引及不可变字节快照，项目目录中的固定版本仍用于原验证链。媒体大文件存 `.vsc-media/`，数据库只存稳定 ID、相对路径、SHA、媒体探测、权属、用途绑定和派生边。原始工作文件、临时供应商 URL、外部任务 ID 不写入剧本或镜头对象。镜头上下文由已批准版本和用途绑定确定性编译；缺少引用、权属或媒体字节失效时不能形成有效生成请求。

图、视频、音频生成请求共用逻辑规格和任务表。路由、模型能力和版本在调度侧解析，业务层不保存供应商参数。任务在远程提交前登记幂等键；提交结果不明时保持 `submission_unknown`，不得自动重发。现阶段只实现**离线的接口、模型注册、路由、计划和状态台账**；既有供应商专用运行脚本尚未接入这个新调度接缝。实际提交、回调、轮询、临时 URL 转存和账单核对须由后续适配器接入及真实样本验证，不能因表已存在视为已跑通。

这一选择增加 SQLite 与 JSON 镜像的同步故障窗口。数据库事务先提交，镜像采用原子替换；异常时停机并显式修复镜像，不从旧镜像逆写数据库。SQLite 适合单机串行编排；多人并发服务化时，应保持同一逻辑契约再迁移到有迁移计划的服务数据库。关系查询是版本与批准权威；全文和向量检索仅帮助发现候选，不替代用途绑定与人工选择。
