# ADR 0004：连续短剧的关系库权威与镜头上下文

- 状态：已采纳，v0.13.0；适用于新建或显式迁移至 `vsc.series-db` 的项目。
- 操作说明：[系列关系指南](../guide/series-db.md)。

60 集以上、每集约 3 分钟的制作需要跨集追踪剧本、人物、地点、声音、镜头、候选和选择。原 `vsc.json` 足以表达状态，但不适合让 AI 按关系检索大量固定版本。采用新的 Profile，保持 production-v2 的阶段、依赖、批准与交付 Gate，同时将项目状态的唯一写入权威改为 `.vsc-series.sqlite3`。`vsc.json` 是旧只读消费者的派生镜像；摘要不一致时阻断操作，`repair-mirror` 只从数据库恢复镜像。旧 Profile 继续以 JSON 为权威，不能静默切换。

批准产物和短文本来源在数据库中有关系索引及不可变字节快照，项目目录中的固定版本仍用于原验证链。媒体大文件存 `.vsc-media/`，数据库只存稳定 ID、相对路径、SHA、媒体探测、权属、用途绑定和派生边。原始工作文件、临时供应商 URL、外部任务 ID 不写入剧本或镜头对象。镜头上下文由已批准版本和用途绑定确定性编译；缺少引用、权属或媒体字节失效时不能形成有效生成请求。

图、视频、音频生成请求共用逻辑规格和任务表。路由、模型能力和版本在调度侧解析，业务层不保存供应商参数。任务在远程提交前登记幂等键；提交结果不明时保持 `submission_unknown`，不得自动重发。v0.13.1 提供火山图像／视频 `submit/poll/parse_result` 实现。v0.14.0 增加 `production_run.series_batch` 固定逻辑请求和共享预算操作，并由统一执行入口做批准复核、预留、提交意图、状态续查和媒体转存。v0.15.0 明确批准语义：run 批准前复核实时 ShotContext，批准后只绑定固定版本，单镜选片或改绑不再使整批失效，过期任务在 plan/submit 时逐个拦下；`video_take`／`dialogue_dry` 作为后期选片不进入生成上下文。v0.16.0 起系列项目的 `selected_takes` 须与素材库登记、权属决定和已批准选片一致，并可从已批准 `video_take` 只读编译草稿；正式选择仍由清单的人工批准确定。离线假 Provider 验证此链；既有供应商专用 CLI 尚未迁入。真实提交、URL 时效、账单、回调服务及在线音频仍需后续脚本和真实样本验证，不能因执行入口存在视为在线已跑通。音频须按独立语音服务的实际权限实现，不能伪称方舟音频已接通。

这一选择增加 SQLite 与 JSON 镜像的同步故障窗口。数据库事务先提交，镜像采用原子替换；异常时停机并显式修复镜像，不从旧镜像逆写数据库。SQLite 适合单机串行编排；多人并发服务化时，应保持同一逻辑契约再迁移到有迁移计划的服务数据库。关系查询是版本与批准权威；全文和向量检索仅帮助发现候选，不替代用途绑定与人工选择。

v0.18.0 将 Agent Plan 的预置音色 TTS 作为 `AudioProvider` 的首个系列实现。音频逻辑请求必须逐字绑定已批准台词、批准覆盖计划中的镜头分配与人物音色；覆盖计划只进音频任务的固定输入，不改变既有图／视频 ShotContext 摘要。响应先落本地暂存并完成解码和摘要校验，转存后只以稳定媒体 ID 供选片。`dialogue_dry` 以台词行作为用途变体，允许同镜多句分别人工选择。发音提示随资产库版本固定，但当前模型请求不声明未验证的词典字段，实际读法仍由人工审听。该决定不改变图／视频接口，也不把离线假响应视为线上成功。
