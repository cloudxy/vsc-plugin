# ADR-0006：命令按职责分组，调用方直接依赖所属模块

- 状态：已采纳，v0.25.0。
- 日期：2026-10-17。

## 背景

scripts 顶层积累了 57 个 Python 文件和一个 Shell 入口。虽然实现已拆入领域包，命令仍以文件名前缀区分职责；11 个文件没有命令行为，只服务旧导入。兼容映射和动态 series facade 使模块归属隐藏在转发和写入传播中。路径又被契约、技能、测试与打包共同消费，移动文件需要同步调整这些接口。

## 决定

1. scripts 只保存实际命令入口，按 kernel、project、story、assets、production、providers、media、post、knowledge、maintenance 分组；供应商按服务方再分目录，顶层只保留索引。
2. 入口直接导入所属模块的 main。库实现位于 src/vsc，工程维护实现位于 tools/maintenance；Python 消费者直接依赖拥有实现的模块。
3. CLI 路径和 Python 模块直接切换到当前结构，删除旧文件、旧导入别名及动态 facade。测试选择使用当前领域／层级 ID，不维护旧选择或路径 aliases。
4. 调用路径同时更新契约、Skill、宿主派生、钩子、worker、工具发现和安装包；内部子进程通过严格的分组相对路径定位命令，不假定所有入口是同目录兄弟文件。
5. 布局和影响分析测试验证入口归属、独立命名空间、工作区外启动和当前引用。新功能必须明确所属模块及验证范围。

## 后果

文件归属和模块接口在同一职责范围内可查，删除中间兼容层提高局部性；CLI、规范和安装包以相同层级交付。旧命令路径及旧裸模块导入需要调用方同步迁移。此决定只调整命令接口与代码归属；作品权威、固定快照、人工决定和数据库迁移协议仍沿现有 ADR。
