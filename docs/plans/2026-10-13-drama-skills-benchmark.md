# VSC 对标 drama-skills：证据、差距与分步吸收方案

- 审查日期：2026-10-13。VSC 基线：`61efd5ebebbfd28d0a9131c3db526d27503028da`，插件 v0.12.0；[上一轮审查](2026-10-11-vsc-workflow-review.md)的 W1–W7 已有[实施记录](2026-10-12-vsc-workflow-implementation.md)。本基线 `vsc_kernel.py doctor` 报告 13 阶段、12 角色、30 契约。
- 对标快照：[zenstory-ai/drama-skills v0.8.1](https://github.com/zenstory-ai/drama-skills/releases/tag/v0.8.1)，完整 commit [`4e48ccbf0f77da757d7cacc6937b1cc59c124845`](https://github.com/zenstory-ai/drama-skills/commit/4e48ccbf0f77da757d7cacc6937b1cc59c124845)，[MIT 许可证](https://github.com/zenstory-ai/drama-skills/blob/4e48ccbf0f77da757d7cacc6937b1cc59c124845/LICENSE)。以下上游观察只对该快照成立；星数、提交数和 `main` 后续内容不作方案依据。
- 决策背景：原方案记录了用户以 drama-skills 为长期对标、暂不吸收 Seedance2-Storyboard-Generator 的选择。本文件只完善方案；**没有批准实施、选择作品素材、安装 Vendor、发起付费生成或替负责人批准创作产物**。
- 核查方法：读取固定 commit 的技能、参考、评测与样例，逐项对照 VSC 的内核、学习链、方法库、制作与后期实现。上游的模型实测是其报告的观察，不算 VSC 本机复测，也不代表供应商当前接口保证。

## 1. 结论与判断口径

VSC 已有固定批准版本、依赖与 Gate、正式制作运行包、预算账本和交付检查；drama-skills 的模型方言、带适用边界的小样本经验、静帧剪辑，以及维护者评测方法值得研究。**本轮目标是让可用经验有可追溯的进入路径，并用一个真实成片验证静帧路径**。不以仓库规模、技能数量或测试数量判定创作效果优劣。

本文将每项能力标成三类：**已有实现**可指到当前代码或契约；**候选改造**只说明拟改的接缝与退出条件；**待实测**需供应商、渲染或人工观看证据。公开方法、上游样片和 VSC 软件测试不能互相替代。镜头工艺默认建议可以被项目负责人覆盖；机器 Gate 只依据已批准项目约束和可验证契约，不因某条方法卡看似有效就自动增加强制规则。

## 3. 差距、接缝与验收

### G01 · 模型方言与请求编译缺少可追溯的局部入口（P1）

**当前。** VSC 的 [导演 Skill](../../skills/vsc-direct/SKILL.md)依赖通用工艺卡，[制作 Skill](../../skills/vsc-produce/SKILL.md)保留中立 ShotPlan/锚点/生成记录，方舟适配器已有 Seedance 模型 ID 与请求构造，但没有一份经过本机验证、可按具体模型版本查找的方言依据。镜头意图、提示词写法和供应商请求参数现在容易被混说为同一规则。

**候选方案。** 保留 ShotPlan 与连续性计划的模型中立语义；在“已批准制作规格 → 已选模型请求”的适配器接缝编译模型专用语法。先对现有 Seedance 2.5 适配器做一条窄范围试验：冻结输入镜头和参考素材，对照有/无候选规则的请求预览及输出；记录模型 ID、实际支持的参考角色、样片、成本、失败例和人工选择。H3/Wan 条目只作研究参考，直到对应适配器和运行条件真实存在。知识存放形式由 U1 的调用点核查决定：请求编译规则归适配器或其邻近规范；可覆盖的创作建议归公共工艺目录，不能在 Skill、Markdown 和 JSON 各建一份权威副本。

**退出条件。** 每条启用规则有固定来源、适用模型/版本、调用点和反例；对已支持模型，dry run 的请求体与已批准规格一致，真实运行仍经原 production-run、预算和人工候选选择；模型未支持或版本不匹配时明确不启用。小样片只能支持限定条件的建议，不能直接变成 Gate。

### G02 · 公共工艺库与既有学习链之间缺少审阅接缝（P1）

**当前。** `knowledge/craft.json` 的 34 张方法卡有来源、阶段、步骤和限制，[`vsc_craft.py`](../../scripts/vsc_craft.py)负责校验与检索；它不是项目批准库。[vsc-learn](../../skills/vsc-learn/SKILL.md)已经能把项目观察变成版本绑定试用、评测、人工晋升与去项目化方法包。缺口是方法包进入公共目录时的人工审阅、适用范围、反例和撤回记录，原方案“无治理机制”说法过宽。

**候选方案。** 沿用现有学习链与 `capability export`，增加一个受审阅的公共方法入口；保留来源类型、证据级别、适用条件和审核状态为不同维度，避免用 `public_method/small_sample/case_verified` 一个枚举同时表示出处、样本量和质量。外部公开资料可先作为有来源的候选建议；项目案例须经人审去项目化，不能复制作品事实或继承原项目批准。先以少量条目验证需要哪些字段，再决定是否扩展 `vsc.craft-catalog/v1`、增加迁移及检索显示，避免为目录增加一套并行 promotion ledger。

**退出条件。** 审阅者能从方法卡追到去项目化证据和有效范围，能看到失败/反例及撤回决定；未晋升候选不会自动注入正式制作；既有 34 张卡与 v1 消费方按明确迁移策略继续可用。工艺卡用于建议与人工审片参考；只有负责人纳入项目规格且可机器验证的条件，才可能进入相应 Gate。

### G03 · 生成条件下的拆镜启发式尚无单一可检索位置（P2）

**当前。** 导演可检索通用镜头工艺，但没有对“H3 某类接触动作先如何试、何时因连续性退回”的范围化条目。上游经验在特定模型、小样本和参考配置下形成，直接复制整份分镜文档会与 VSC 既有 ShotPlan、状态时间线和 G01 的证据来源重复。

**候选方案。** 从固定来源挑 1–2 条有明确反例的启发式，经 G02 的公共方法入口登记；director 检索时显示模型范围、镜头类型、适用条件和可覆盖性质，产物只引用所用规则 ID 与选择理由。若项目未选相应模型，则保留通用拆镜判断，不注入专有经验。

**退出条件。** 试验镜头能追到所用规则及适用边界；规则缺席、不适用或创作者明确覆盖时，原有 ShotPlan Gate 结果不变；样片反例可导致缩窄或撤回，不会原地改写历史结论。

### G04 · 静帧成片路径尚未通过真实导出验收（P2）

**当前。** [`remotion_plan.py`](../../scripts/remotion_plan.py)接受 image 片段，生成的 Remotion 画面目前只以静态 `Img` 显示，没有运镜参数。[`jianying_export.py`](../../scripts/jianying_export.py)会把 image 片段写入“未迁移”警告，并要求至少一个 video；因此不能说剪映已支持全静帧草稿。已有 timeline/selected-takes 版本绑定与轻量 Profile 只证明结构接缝存在，不证明静帧运镜、声音桥和成片已跑通。

**候选方案。** 先选 Remotion 作为最小成片适配器，给 image 片段增加受限的起止取景、缩放/平移和缓动语义；规定画幅填充、安全区、相邻静帧切点和无效参数的处理。用获选且有权属的图片与声音走正式时间线、实际渲染、解码 QA、字幕/环境声/J/L cut 核验和人工回看。先使用已有、获授权音轨；云端 TTS 若未通过认证，不写入最小路径的成功条件。剪映的“原生图片轨”或“先视频化再导出”另作兼容选择，不能借 Remotion 通过冒称剪映通过。

**退出条件。** 一条有明确创作目标的全静帧小样完成可打开的成片；镜头覆盖、选用媒体 SHA、音画时序与交付 QA 全部可回溯；制作账本显示本次 **零视频生成任务/零视频用量**，图片、音频、渲染等实际资源仍如实记账或标记未知。人工回看确认运镜不破坏构图和文字可读性；Remotion 依赖安装、类型检查、实际渲染各有真实执行记录。

### G05 · 跨版本案例证据尚未覆盖真实制作回放（P2，条件工作包）

**当前。** 上游的[八集公开结构样例](https://github.com/zenstory-ai/drama-skills/blob/4e48ccbf0f77da757d7cacc6937b1cc59c124845/examples/golden-project/README.md)、[单集实跑记录与 16 题材案例说明](https://github.com/zenstory-ai/drama-skills/blob/4e48ccbf0f77da757d7cacc6937b1cc59c124845/evaluations/README.md)承担不同用途，不能合称为“八集真实作品金标”。VSC 的隔离合成回归能检查协议行为；目前未有获授权的真实作品跨版本复跑及观看质量基准。

**候选方案。** 先定义两类案例：公开的最小合成 fixture 检查状态/Gate/依赖/交付行为；获授权的真实制作回放留在作品或受控评测区，固定输入版本、适配器/模型版本、选择与人审记录。只有来源权利、去项目化和发布范围经负责人确认后，才提取可公开的结构化最小片段进入 tests；没有权利时只保存不含作品事实的汇总与测试接口。评测应含反例、返工和方法失效条件，质量判定须由真实观看者按预先写明的标准作出。

**退出条件。** 公共 fixture 只声明工程回归；真实回放能在固定版本上比较行为和人工结论，并清楚显示不可复现的供应商/媒体部分。缺授权或样例 A 尚未完成时，本工作包继续挂账，不以新造合成案例称作真实金标。

| U4 | Remotion 静帧成片；时间线 → 渲染适配器 | 最小运镜语义、真实成片、QA、人审和账本记录 | §3 G04 全部通过；剪映兼容另评。可与 U1–U3 并行设计；真实小样需项目素材与负责人决定 |

U0 应最先完成；U1–U3 只选小范围规则，不承诺整批移植。U4 是验证用户能否做出静帧成片的独立产品结果，不以 U1–U3 全部完成为前提。U5 不能反向阻塞已能验证的工程改动。每个工作包均按 [VSC 架构维护流程](../../skills/vsc-architecture/SKILL.md)直接在 `main` 实施、运行完整本地 CI，并在有对应真实案例时复跑；行为、契约或 schema 变化另升版本、写 release notes 和迁移说明。

## 5. Vendor、批准与兼容约束

- U0 的临时固定快照研究不等于 Vendor 安装。若只是链接和概括公开方法，用 `reference_only`；确需把上游表达/实现移入 VSC，才按 [Vendor 治理](../governance/vendor-governance.md)评估 `ported`，在锁文件登记完整 commit、许可证证据、用途、范围和责任，并在移植文件保留应有许可证声明。`vendor/` 源码本身不提交 Git；安装仍需用户明确要求。
- 方言建议不能改变已批准 ShotPlan、资产身份、声音方案或生产预算。新模型或不同版本必须先验证供应商当期接口、适配器可用性、请求预览和项目授权。`configured=true` 或一条上游样片不等于生产可用。
- 任何外部方法的测试、项目 pilot、公共目录登记与项目批准是不同决定。新卡不隐含新 Gate；未审阅候选、分析用来源及没有权利的素材不进入正式制作。
- 旧作品、批准快照与旧 Profile 保持可追溯；变更仅通过显式新版本与迁移。不得把静帧路径验证成功写成视频生成能力或剪映导出能力已验证。
- 本计划的剩余人工决定是：选哪条真实小样、允许使用哪些素材与供应商/预算、是否把某项受控试验的方法晋升为公共建议。负责人未作决定前，可以完成 U0 和不依赖作品的局部工程验证，不能代作创作批准。
