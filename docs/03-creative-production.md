# 03 · 短剧与短视频创作体系

本文描述 VSC 的影视创作领域流程。各阶段可以按业务重组；以下默认场景是小说改编的连续短剧。阶段检查点是提案，不是已经在真实项目中验证过的标准。

## 1. 先区分作品类型

| 类型 | 主要组织单位 | 通常需要维护的内容 | 不宜默认的规则 |
| --- | --- | --- | --- |
| 连续短剧 | 季／篇章、集、场景、镜头 | 人物弧、跨集因果、伏笔与兑现、资产连续性 | 每一集都机械断在同一种悬念上 |
| 单条剧情短视频 | 一个完整叙事单元 | 有限时间内的信息、情绪与结局 | 必须为下一集留钩子 |
| 品牌／产品短视频 | 核心信息与受众行动 | 产品事实、品牌表达、素材版本和用途 | 必须采用人物冲突型剧情 |
| 音乐／氛围短片 | 乐段、情绪段、视觉节奏 | 音画关系、主题意象、风格一致性 | 必须先写传统对白剧本 |

“短”首先意味着可用的观看时间有限。具体时长、画幅、字幕安全区域、平台交付规格由项目与平台配置确定，不写成跨平台永久规则。

对连续短剧，VSC 建议同时设计“本集让观众得到什么”和“系列还留着什么问题”；对单条视频，重点检查本条表达能否独立成立。这是创作策略，适合程度要通过样片检验。

## 2. 全流程及交接产物

| 阶段 | 核心工作 | 交付产物 | 进入下阶段前检查什么 | 不通过时主要返回哪里 |
| --- | --- | --- | --- | --- |
| S0 创作委托 | 明确受众、表达、类型、预算、素材用途与交付目标 | CreativeBrief、素材清单、项目策略 | 目标能否说明白；输入和使用范围是否明确 | 委托与素材准备 |
| S1 理解素材 | 识别人、事、因果、时序、世界规则和原文证据 | StoryBible、SourceMap、待确认问题 | 事实与解释是否分开；关键因果是否完整 | 素材阅读 |
| S2 改编设计 | 选择主题与视点、压缩线索、安排分集与信息揭示 | AdaptationPlan、EpisodeBeats、改编记录 | 人物动机是否成立；删改是否符合改编契约 | 理解或改编 |
| S3 剧本 | 外化行动，组织场次、对白、声音和节奏 | Screenplay、对白表、初步时长 | 可表演、可听、可拍；朗读时长是否合理 | 剧本或分集 |
| S4 视听与资产设计 | 角色、场景、道具、动作、声线、镜头、运镜和转场 | VisualBible、资产规格、ShotSpecs、声音方案 | 是否足以共同制作；复杂镜头是否可行 | 设计或剧本 |
| S5 分镜预演 | 把分镜、临时对白、音效与音乐放入时间线 | Animatic、临时混音、预演评审 | 信息是否看得懂；情绪、动作和对白是否放得下 | 镜头设计或改编 |
| S6 正式素材制作 | 生成／拍摄图片、视频、表演、对白、音效和音乐 | 各类 Take、质量记录、选择结果 | 叙事意图、身份、动作、连续性和可剪辑性 | 对应资产或镜头 |
| S7 剪辑与后期 | 选 take、调整节奏、补镜、合成、调色、混音和字幕 | Timeline、Mix、字幕、审片版 | 整体叙事与视听技术是否成立 | 局部制作或剪辑 |
| S8 审片与交付 | 创作验收、技术验收、用途检查与打包 | ReleaseDecision、DeliveryManifest | 采用了哪些确定版本；交付规格是否满足 | 对应失败环节 |
| S9 反馈与复盘 | 收集理解测试、制作数据及可获得的传播反馈 | ExperimentReport、模板改进提案 | 结果是否支持原假设；哪些改变有依据 | 下一轮创作 |

S4 内部允许资产与分镜迭代，S6 允许镜头并行。S5 通过后只冻结用于本轮制作的基线版本；以后仍可修改，但应说明影响与成本。

分镜承担从文字到画面序列的工作，带时间的分镜预演有助于观察剪辑关系；可参考 [ScreenSkills 分镜职业资料](https://www.screenskills.com/job-profiles/roles/storyboard-artist/)。VSC 将其设为优先验证点，是本提案的工程与创作选择。

## 3. 小说理解：建立可以回查的故事底稿

### 3.1 长篇文本的处理

先为原始文件建立固定版本、章节和段落／字符定位。分块处理时提取事件、角色别名、关系、时间、地点和规则，再做跨块合并与矛盾检查。检索和摘要是阅读辅助，不保证关键事实一定被保留。

每条 Claim 区分：

- `source_fact`：原文明确写出的内容，附 SourceSpan。
- `interpretation`：对动机、主题或关系的解释，附证据和备选解释。
- `adaptation`：为影视表达作出的改变，附决策与理由。
- `invention`：新增桥段、对白或设定，标明用途。
- `unresolved`：尚不能确定，需要回读或创作者决定。

事实与人物自述也应区分。一个角色说“我没有来过”是“他说过这句话”，不自动等于故事世界中他确实没有来过。

### 3.2 故事圣经的最小内容

主题与创作立场；世界规则；角色目标与阻力；关系变化；重要事件及因果；故事时序；信息揭示顺序；尚未兑现的铺垫；术语与命名；不可改项与可改项。

设定不足可以提出候选，但要保留“这是推断”这一事实，避免一条早期幻觉在后续图像、对白和动作中不断放大。

## 4. 小说改编成剧本的转换机制

### 4.1 改编契约

在写分集前约定三个集合：必须保留、允许调整、明确新增。还应说明忠实目标是事件、人物动机、主题、氛围或语言中的哪几项。

每次重要调整记录：原文依据 → 原来的戏剧功能 → 新的视听表达 → 改动代价 → 采用理由。例如合并两个功能接近的配角，可能降低制作成本，也可能损失关系层次，不能只记录“已精简”。

### 4.2 从叙述到可见、可听的行动

| 文学表达 | 可选择的影视表达 | 核验重点 |
| --- | --- | --- |
| “她开始怀疑他” | 停住递物动作、视线移向证据、改变提问方式 | 观众能否找到怀疑的依据 |
| 大段世界设定 | 道具、行为后果、短对白或必要旁白 | 是否恰好在观众需要时给出 |
| 长时间回忆 | 精选闪回、视觉线索或当下行动中的信息 | 观众是否能区分时空 |
| 抽象权力关系 | 站位、空间占有、打断、谁能离开场景 | 表达是否依赖未交代的文化假设 |
| 描写激烈动作 | 有目的的动作段与反应镜头 | 可理解性、动作能力和制作成本 |

旁白是可用表达手段，并不应被一概禁止；选择依据是作品形式和它提供的信息价值。

### 4.3 每个 Beat 写清楚什么

Beat 是有意义的信息、行动或情绪变化单位。推荐记录：谁想要什么、阻力是什么、采取什么行动、结果发生什么变化、观众知道了什么、下一段为何发生。

行动与事件组织的重要性可参考[亚里士多德《诗学》](https://classics.mit.edu/Aristotle/poetics.1.1.html)。VSC 不据此要求所有现代作品服从古典悲剧形式。

分集先保持因果和人物选择，再调整密度。钩子、反转、爽点或悬念属于可选创作策略，应说明其功能，不用统一秒数套在所有作品上。

## 5. “人物、动作、声音、场景建模”的分层

这里的建模首先是把创作对象表达清楚。技术建模和训练只在制作路线需要时使用。

| 对象 | 语义／设计层 | 参考资产层 | 可选技术实现层 |
| --- | --- | --- | --- |
| 人物 | 身份、年龄范围、目标、性格、关系、可变与不可变特征 | 多角度参考、表情、服装变体、比例和色彩 | 3D 网格与材质、绑定、特定模型适配或训练 |
| 动作 | 目的、起止姿态、节拍、力量、物体交互、情绪 | 姿态图、动作分解、参考片段 | 骨骼动画、动作捕捉、姿态控制或视频表演迁移 |
| 声音 | 声线、口音、音域印象、语速、人物说话习惯 | 试听片段、发音表、情绪表演样本 | TTS 声音 ID、授权声音克隆或其他语音系统 |
| 场景 | 空间关系、出入口、时间、光源、可见道具 | 布局图、方向图、参考图、光照与天气变体 | 3D 场景、数字布景、渲染或真实拍摄地点 |

2D 图生视频通常可以从前两层开始。人物参考图不等于可操纵的 3D 角色，动作提示词不等于精确骨骼动画，声音设计不等于训练模型。

声线和对白表演分开：同一角色可以低声、喊叫、迟疑，但应保留可辨认的身份。声音设计的维度可参考 [ElevenLabs 官方文档](https://elevenlabs.io/docs/eleven-creative/voices/voice-design)。

## 6. 每个镜头至少说清楚什么

| 方面 | 需要的信息 |
| --- | --- |
| 身份与目的 | 集／场／镜 ID；对应 Beat；观众应该获得的信息或情绪 |
| 时长 | 计划使用时长、素材余量、对白与动作节拍、可调整范围 |
| 主体与状态 | 哪些角色／道具；服装、姿态、表情、手持物、前后状态 |
| 场景 | 场景变体、空间站位、光源、时间、天气 |
| 构图 | 景别、角度、主体位置、视线与画面方向、纵深 |
| 相机 | 固定或移动；起止构图、运动方向、速度与叙事目的 |
| 主体动作 | 谁做什么；先后顺序；与物体和他人的关系 |
| 声音 | 对白、环境、动作音、音乐、静默、画内／画外关系 |
| 连续性 | 与相邻镜头的轴线、视线、光线、动作和道具状态 |
| 剪辑衔接 | 切点意图、转场、音频跨镜方式、所需余量 |
| 制作约束 | 必须保留的元素、允许变化、能力要求和替代方案 |
| 检查标准 | 什么构成通过，什么错误必须重做 |

焦段等摄影参数只有在真实相机或 3D 系统中才可能是精确控制；对部分生成模型，它们只是影响画面观感的提示。适配器要说明控制精度，不能伪装成物理保证。

## 7. 区分主体动作、运镜、转场

主体动作发生在画面世界里；运镜改变观察位置或画面构成；转场发生在两个片段的衔接处。三者分别存储，避免一个含混句子承担全部控制。

例如“人物向门口走，镜头缓慢后退，门框遮挡后切入下一场”：前半段是主体动作，中间是相机运动，最后是转场设计。若生成器无法稳定完成，镜头可拆分，但需保持观众对空间与行动的理解。

图生视频时，参考图与运动提示承担不同作用；[Runway 指南](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)明确区分图像提供的视觉信息和文本描述的动态信息。VSC 据此设计独立的 ImageSpec 与 MotionSpec，再按供应商合并请求。

转场从叙事需要选择：直接切、动作匹配切、声音提前进入、声音延续、叠化或有意的跳切等。不要把每次镜头衔接都设计成复杂生成特效。

## 8. 声音在预演阶段进入流程

声音方案至少包含对白、环境、动作音效、音乐和静默。每条 SoundCue 说明功能、进入退出位置、与画面的关系和素材来源。

建议顺序：对白试读 → 粗定表演和镜头时长 → 带临时音轨的预演 → 正式声音／视频制作 → 对齐与混音。音乐驱动的作品可以先定音乐结构，原生音画生成可以共同制作，但仍需保留音轨关系和必要的替换路径。

背景音乐需回答“此处为什么需要它”。例如线索出现时撤掉音乐可能比升高音量更清楚。旁白、对白和音乐的可懂度在具体设备与播放环境下审听；平台响度等参数由交付模板提供。

口型镜头要明确采用：先定对白后做口型、原生音画生成、表演参考或后期同步。若对白改变，系统应识别口型与画面是否也受影响。

## 9. 从图片到视频的制作子流程

1. 根据确定的镜头规格绑定角色、场景、道具与风格版本。
2. 生成或导入关键帧；检查身份、构图、物体关系和文字。
3. 选择合格关键帧，必要时修图，建立运动与声音规格。
4. 根据能力选择图生视频、首尾帧或多参考路径。
5. 生成有限候选，保存请求、任务和费用记录。
6. 检查时序中的身份变化、肢体／道具错误、动作、相机和声音。
7. 按具体原因选择修参考图、简化动作、拆镜、换能力或再生成。
8. 接受可剪辑候选，保留媒体余量和相关版本，交给时间线。

图像只证明某一帧可用，不能证明运动过程中都可用。先审关键帧能减少部分错误，但其实际收益属于待验证假设。

官方 [ComfyUI Wan 示例](https://docs.comfy.org/tutorials/video/wan/wan2_2)展示多种视频生成路线，适合用来实现此处的生成子流程；整个创作项目还需要独立的故事、资产、评审与剪辑管理。

## 10. 连续性是状态管理

连续性不仅是“脸相似”。建议分别检查：

- 身份：脸、体型、声线、角色命名。
- 造型：服装、饰品、发型、伤痕及其剧情变化。
- 空间：站位、视线方向、出入口、摄影轴线和屏幕方向。
- 行动：物体在哪只手、门开到什么程度、上一动作是否结束。
- 环境：光线、天气、背景人物、道具布局。
- 叙事：人物此刻知道什么、目标是什么、情绪为什么改变。

每场戏维护状态基线，每个镜头声明前置和后置变化。场记职责可参考 [ScreenSkills](https://www.screenskills.com/skills-checklists/scripted-film-and-tv/script-supervisor-department/script-supervisor-skills/)。具体状态结构是 VSC 的设计推论。

自动检测可以提示可能的问题；例如人物相似度并不能证明角色身份或表演正确。重点镜头由具有相应职责的评审者作最终判断。

## 11. 剪辑与交付

时间线是成片的权威组合记录：素材版本、入出点、轨道、变速、转场、对白、音效、音乐、字幕和标记都可追溯。以整数帧和有理数帧率表达视频时间，音频保留采样率与精确位置，避免累计舍入误差。

素材时长与成片使用时长不同。叠化可能需要片段余量，J-cut／L-cut 等音频跨镜不会自动增加视频总时长。实际总时长从时间线计算，不只把镜头计划秒数相加。

交付包包含：成片、约定的字幕／音轨／封面、时间线或剪辑交换文件、所选素材清单、版本与来源记录、评审结论和交付规格。保留可编辑工程能支持改横竖版、多语种、替换音乐或局部修订。

[OTIO](https://opentimelineio.readthedocs.io/en/latest/)可作为剪辑交换基础，但复杂特效、字体或特定软件的功能需要单独验证与打包。

## 12. 评价与学习

| 维度 | 问题 | 证据方式 |
| --- | --- | --- |
| 叙事 | 观众理解谁想做什么、为何变化了吗？ | 试看片后的复述、提问和具体评语 |
| 情绪与表达 | 表演、节奏和视点是否实现意图？ | 创作者审片与目标受众反馈 |
| 连续性 | 角色、道具、动作与空间是否成立？ | 状态对照、逐镜核查、辅助检测 |
| 媒体技术 | 播放、画幅、帧率、音轨、字幕是否合格？ | 文件探测、解码检查、目标设备回放 |
| 制作效率 | 花费多少时间与成本才得到可用内容？ | 运行账本、人工工时、失败分类和等待时间 |
| 业务表现 | 作品是否达到事先约定的目标？ | 合法可得的投放／平台／反馈数据 |

技术验收与使用效果验证应分开，参考 [NASA 的验证与确认区分](https://www.nasa.gov/reference/5-4-product-validation/)。对创作而言，文件完全合格仍可能表达失败。

传播数据会受到受众、分发、发布时间、内容主题等影响。一次播放量变化不能直接证明某个镜头策略有效。把反馈转成下一轮可比较的小实验，并记录限制。

只有明确改善或可靠避免错误的经验，才进入团队模板；单次偶然成功的提示词保留为案例，不立刻升级为普遍规则。
