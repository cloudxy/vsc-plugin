# v0.16.0

`vsc.series-db` 中，数据库记录的选片与正式选片清单不再可能各说各话。

## 行为变化

- 系列项目的 `vsc.selected_takes` 在登记、批准和 Gate 检查时核对数据库：获选媒体须已导入系列素材库；`usage_rights` 必须等于人审权属决定（`owned`／`licensed`，系列项目不使用 `project_generated`）；镜头已有批准的 `video_take` 或 `dialogue_dry` 时，同模态条目必须选同一份字节。旧 Profile 的选片规则不变。

## 新增

- `vsc_series_selection.py compile PROJECT --episode EP --out FILE`：只读地从本集已批准的 `video_take` 编译 `vsc.selected-takes/v1` 草稿，选择人取自绑定决定，并打印含 animatic 与各生成记录依赖的登记命令。缺唯一生成记录、take 对象或权属确认时报错指出缺项；它不批准清单。手工视频、对白干声与静帧仍按模板补写条目。
- `vsc_series_selection.py check PROJECT FILE`：预检手写清单与数据库是否一致。

## 验证与边界

离线回归跑通一条视频链：批准 run → 假 Provider 提交与续查 → 转存 → 导出并登记生成记录 → take 对象 → 权属决定 → 批准 `video_take` → 编译清单，编译结果通过完整的选片清单项目校验；改写权属、换成未登记媒体或选其他视频时均被拦下。**没有调用火山方舟。** 成片效果、在线生成与真实审片仍待用户提供脚本和素材后验证。仓库内没有 `series-db` 作品，无需迁移。
