按执行方案 §13 B0–B2 首批实施，修复审计缺陷 F01–F10、F12（F11 正式 run 接线与 F07 批注范围迁移留待下一批）：

- **F05/F06 硬停事务内统一**：`check_script_confirmation` 移入 `_create_artifact` 事务内统一消费——类型→阶段归属只由固定 Profile 解析（伪造 `stage` 无效）；目标范围逐一覆盖（仅 A 集批准时 B、A+B、项目级产物全部拒绝；项目级产物须项目级剧本）；`script-submit` 只接受剧本类型并必须携带准确 `draft_revision`（F04）；提交沿既有已批准剧本的固定 stream 复用 `artifact_key` 并记录基线（不再产生可互相绕过的两条 current 流）；覆盖范围内存在**待审修订**时相关新制作以 `script_revision_pending` 暂停，退回后自动恢复；范围语义与登记一致（未声明对象范围即项目级）。
- **F09/F10 共用请求编译（B2-01）**：新增 `xai_grok/spec.py` 纯编译器，CLI、series、PG 三入口同一 payload 或同一拒绝——时长/分辨率与模式上限、参考/关键帧/预置声音数量、经典模型组合（无尾帧/关键帧/声音、禁首帧+参考、10 秒上限）全部前置；`GrokVideoProvider/GrokImageProvider` 实现 `preflight`（含登录态检查），PG worker（既有挂点）与 series `dispatch` 在预算预留与提交意图**之前**执行，本地非法请求 0 POST、0 unknown；series/PG 工厂支持受支持逻辑参数（`resolution/aspect_ratio/generate_audio`）显式覆盖，未声明参数一律拒绝不再静默丢弃；CLI 图像编辑 `--count>1` 提前拒绝，编辑记录不再登记未发送的画幅/分辨率。
- **F12 输出验证与稳定账号**：视频下载后经 ffprobe 完整解码验证（HTML/截断文件删除坏文件并可续接重下，不记 succeeded）；任务归属改用登录账号稳定身份（`user_id`，缺省退 email）的摘要——同账号刷新 token 后旧任务可续查，跨账号仍拒绝。
- **F08 差异与基线**：`script_diff` 补齐行动 `narrative_refs`、静默 `duration_ms/purpose` 的比较；比较基线按精确范围选取（项目级稿不再拿某分集当基线）。
- **F01/F02/F03/F04/F07 前端**：保存会话绑定 project+scope，串行保存队列（保存中继续输入不丢最后一句），过期响应与切换后的定时器不写当前会话；`readEditor` 按稳定场/行身份合并编辑字段，保留引用与静默语义；提交等待成功保存（失败不得提交）；待确认审阅展示**被冻结 artifact 正文**（含范围/场次/SHA 一致性核对）而非当前编辑稿；分集导航按 work→episode 分页重建；批注操作只刷新元数据不覆盖编辑器。
