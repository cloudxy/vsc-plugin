# v0.15.0

`vsc.series-db` 补齐生成结果进入后期的离线接缝，并修正 v0.14.0 中会让整批任务失效的批准语义。

## 行为修正

- **已批准 run 不再因后续选片整体失效。** v0.14.0 每次校验 `series_batch` 都按实时 ShotContext 重算全部任务；某一镜批准首帧、构图或其他绑定后，整份 run 及依赖它的生成记录、选片清单都会判为失效，同批其他镜头也无法预留预算或提交。现在 run 在批准前完整复核实时上下文；批准后只核对固定版本、计划摘要、分集范围与原生单位。`plan` 与 `submit` 仍逐任务比对当前上下文，过期任务须进新 run 重新批准。`approved_inputs` 中的产物被替代时，run 仍按原规则失效。
- **后期选片不再进入生成上下文。** `video_take` 与 `dialogue_dry` 绑定只供后期使用；首尾帧、构图、道具和资产参考仍是生成输入，批准后会改变对应镜头的上下文。
- **重复续查不覆盖人工结算。** 转存完成只把仍处于 `submitted_unknown` 的预留记为 `usage_unknown`；负责人已录入实际用量的预留保持 `settled`。

## 新增

- `vsc_series_dispatch.py resume-pending`：按固定外部编号批量续查，并补做此前中断的转存，不提交新任务。单个任务失败会记为 `poll_error` 事件并排到队尾，不中断整批；出现失败时命令退出码为 1。转存完成写入 `transferred` 事件。
- `vsc_series_export.py`：把已转存任务编译为 `vsc.generation-record/v1` 草稿。锚点摘要由任务钉住的资产库与状态版本重算；首尾帧按媒体库来源写入 `inputs.first_frame/last_frame`；参考素材带路径与资产 ID；用量取批准 run 的原生单位上限，金额保持未知。
- `vsc_series_query.py`：只读关系查询，包括 `shot`、`shot-jobs`、`asset`、`episode`、`scene`、`media`、`line`。`media` 可列出一份素材的权属决定、生成来源、派生关系、用途绑定和引用它的任务；`scene` 返回一场内逐镜入出点状态与跨集边界。
- Remotion 渲染计划为 image 片段增加受限 `still_motion`：焦点 0..1、缩放 1..1.5，帧驱动插值，画面不露边。

## 验证与边界

离线回归覆盖：选片后 run 仍有效、过期镜头单独受阻；下载失败后补做转存，且不覆盖人工结算；生成记录导出、关系查询和静帧运镜帧计算。**没有调用火山方舟，也没有实际渲染成片。** 在线模型、URL 时效、账单、音频语音服务、真实静帧成片与 60 集试点仍须用户提供脚本和素材后验证。

旧 Profile 无需迁移。`series-db` 项目中已批准 `video_take`／`dialogue_dry` 绑定的镜头，其上下文摘要会变化；未提交任务按新摘要重新计划。当前仓库内没有 `series-db` 作品受影响。
