# VSC v0.2 升级方案：从架构提案到独立编排器骨架

日期：2026-10-01（历史 v0.2 升级记录）。此版不承诺“自动做出好短剧”；它先将研究结论固化为可运行、可验证、可被不同团队扩展的工作流内核。当前实现与角色数量以 `workflow/`、`scripts/vsc_kernel.py doctor` 和 [ADR-0001](../adr/0001-workflow-kernel.md) 为准。

## 研究结论如何落地

| 研究共性 | VSC v0.2 的实现 | 刻意不做 |
|---|---|---|
| 创作不能由提示词替代意图 | `/vsc` 先识别受众、目标、约束、来源和责任人，再选 Profile | 看到小说就直接批量生成视频 |
| 复杂工作需要专业分工与清晰责任 | 总编排器调度故事分析、改编、编剧、导演、资产、制作、剪辑、审片八种角色 | 让一个“万能代理”既创作、又审自己、又批准发布 |
| 不同工作室需要不同顺序与标准 | `profiles/` 把阶段、必需产物和自动化策略定义成可复制 JSON | 在状态机中写死一家公司的流程 |
| 生成媒体需要参考、版本与选择 | artifact 记录类型、文件 SHA、依赖、状态与负责人；候选 take 不自动进入成片 | 将覆盖后的文件或供应商历史当作可追溯版本 |
| 返工要能找到根因 | Gate 检查累计前置产物是否已批准；审片问题退回最早责任阶段 | 靠重复抽卡掩盖剧本、资产或分镜问题 |
| 工具变化不该推翻创作资产 | `adapters/` 只定义生成任务的边界，核心不绑定模型 SDK | 在核心逻辑写死某一家的 API 或价格 |

公开生成工具的实践支持“参考资产—镜头候选—编辑”的分层：Runway 将角色/场景 references、图像到视频与多角色表演分开，并建议用角色板和故事板保障一致性；其官方文档也明确把 5–10 秒镜头视作适合逐镜生成和评审的单位。[Runway References](https://help.runwayml.com/hc/en-us/articles/40042718905875-Creating-with-Gen-4-Image-References) [Runway 长视频工作流](https://help.runwayml.com/hc/en-us/articles/26871350018835-How-to-create-longer-videos-and-films) VSC 不把这些供应商做法当成普遍真理，而将其抽象成可替换的资产、镜头、take 和时间线协议。

VSC 对来源、产物、活动与责任人的区分，借鉴 W3C PROV 对实体、活动、主体和责任关系的建模；具体数据结构是 VSC 的工程推论。[W3C PROV Primer](https://www.w3.org/TR/prov-primer/)

## 目标架构

```mermaid
flowchart LR
  U[用户需求] --> M[/vsc 总编排器]
  M --> P[选择 Profile 与项目策略]
  P --> A[改编/剧本]
  A --> D[导演/资产]
  D --> PV[预演]
  PV --> G[图像·视频·声音候选]
  G --> E[剪辑/审片/交付]
  E -. 返工依据 .-> A
  E -. 返工依据 .-> D
  X[外部来源或交接包] --> A
```

新手只需一句话进入编排器；熟手可直接调用 `/vsc-adapt`、`/vsc-script`、`/vsc-direct`、`/vsc-assets`、`/vsc-produce`、`/vsc-post`。二者使用同一项目状态和 Profile，不是两套产品。

## 已实现内容

1. 独立插件清单、`/vsc` 总编排入口和六个熟手直达命令。
2. 八个职责明确的角色定义；创作、评审与批准互相分离。
3. 三个可扩展 Profile：通用叙事、小说连续短剧、品牌叙事短视频。
4. `scripts/vsc_state.py`：初始化、来源登记/导入、产物与依赖登记、审批决定、阶段 Gate、Profile 查询和中立交接包校验。
5. `creative-handoff/v1`：来源插件或人工都可生成的文件协议；VSC 只导入，不调用或嵌入来源插件。
6. 生成适配器边界与自动化策略：预留图像、图生视频、声音能力，但不假装已经接入供应商或持有密钥。

## 验收与下一版

本版验收：初始化稳定项目 ID；错误 Profile 被拒绝；来源与已批准产物是 Gate 的前提；依赖不存在被拒绝；外部交接包只接受通用格式；决策理由与责任人可回查。

v0.3 应在真实项目验证后再做：一个本地媒体存储/数据库实现、至少一个图像与一个图生视频适配器、任务队列、成本账本、逐镜连续性检查、预演时间线和真实审片数据。供应商选择、价格、版权、声音权利和发布策略都必须在实际账户、地区和项目授权范围内单独验证。
