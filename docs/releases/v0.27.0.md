# v0.27.0 — 剧本工作副本、人工确认硬停与剧本工作区

落实升级方案 Q1：剧本完成后必须停在资源中心等待人工确认，未确认不得进入正式设计与资产生产。

- **剧本工作副本**（迁移 `0006_script_workspace`）：`script_drafts` 是资源图中唯一允许就地更新的表——自动保存走自己的 `draft_revision` 乐观并发序号，不产生正式 artifact 版本、不占用项目 revision、不触发关系投影。提交确认在同一事务内经既有 `_create_artifact` 冻结为不可变 `screenplay` 版本；`script_notes`／`script_note_decisions` 为追加式批注与处理决定，批注只锚定场次／行身份，不进入正文。
- **人工确认硬停**：`create_artifact` 对 script 之后阶段的正式产物统一校验"当前范围存在已批准且 current 的剧本"；未确认时以 `script_confirmation_required`（409）拒绝登记（CLI、网页与 API 同一入口；任务创建、试片与提交沿用既有 Gate）。范围按剧本 artifact 的对象范围与创建产物的祖先链判定，项目级产物需要项目级剧本确认。
- **剧本工作区**（面板新"剧本"页签）：场次／行动／对白／静默编辑、防抖自动保存（保存中／已保存／失败／并发冲突显示）、行级批注与解决、与已批准基线的结构差异比较（`script_diff`）、"提交人工确认"与批准／退回（走既有 artifact 决定，须 confirmed 会话）。创作工作台概览新增"剧本确认"区块。
- **API**：`GET /{project}/script-draft`、`GET .../script-draft/compare`、`POST .../script-draft/autosave`（会话绑定、非正式写）；`script-submit`、`script-notes`、`script-note-decisions` 进入统一写端点。

验证：迁移在隔离真实 PostgreSQL 通过（metadata 比对无差异）；服务层 6 项、HTTP 1 项、diff 单测 3 项覆盖自动保存不产生正式版本、过期修订冲突、提交→批准→放行／退回→重提、未确认阻断（分集与项目级负例）、无会话 403、未 confirmed 422；assets／project／production 全域带真库回归通过（0 跳过）。本机资源数据库已先备份再显式迁移到 `0006_script_workspace`。真实浏览器中的编辑手感、撤销重做、长篇分集定位与键盘路径尚未实测，AI 差异逐处接受／拒绝未实现，按执行状态记录待办。
