# 在实际任务使用创作方法

本方法服务当前阶段内部的探索、选择和修改，不增加作品状态、批准或默认生成用量。教材是通用参考；项目事实和适用批准仍来自固定产物。普通用户只看作品、差异和必要决定。

## 按问题选择并固定读取

1. 先说清当前问题与不可改项。局部明确修改直接处理；需要方法时用`python3 -B scripts/knowledge/craft.py search <问题> --stage <当前阶段>`，先选一项相关方法，不全量装入方法库。
2. 用`python3 -B scripts/knowledge/craft.py show <ID> --with-teaching`读步骤、正反例和限制。保留返回的`teaching_sha256`、教学path/anchor和工作流发布版本；`teaching=null`表示只有原卡，不是已经读过案例。超过软目标仍读完整章节，不能删去反例。
3. 编排者把问题、保留项、固定输入和方法`ID/path/anchor/teaching_sha256/发布版本`写入现有context任务文本，先build最小包。角色consume后实际执行`python3 -B scripts/knowledge/craft.py show <ID> --expected-sha <固定摘要>`。卡、来源或正文漂移时停止使用旧任务并重建输入，不能静默换最新教学。
4. 专业角色在原剧本/设计/时间线差异中指出运用位置、保留项、选择代价及未采用原因；结果沿原return协议回收。编排者读过不代替角色实际读取。不为此另写一套“学习完成”产物，不自动批准或改写角色记忆。
5. 新任务重新检索适用方法/有效记忆；教学更新不改旧固定作品。通用方法、项目记忆提案、受控能力晋升分别走原入口；PG未支持capability/pilot时明确拒绝，不切回JSON制造第二权威。

方法交接按[消费者检查](review-and-feedback.md#consumer-check)执行：接收角色先读固定结果，再在自己的原设计、输入绑定或时间线中定位实际使用处。验证新方法时用最小 context 传入同题输入、具体章节和成果用途，观察角色能否产生可接续内容，以及接收者能否继续；角色只复述规则或 return 成功仍不算完成该验证。无独立执行者时按职责顺序自检并注明，不能冒称独立复核。

## 从教学到正式专业方法 <a id="professional-method"></a>

教学读取的`teaching_sha256`固定卡、来源与章节；`vsc.capability-method/v1`的`method_sha256`固定方法包内容；项目方法产物的UUID与`sha256`固定登记版本。三者用途不同，不能拿卡名或教学摘要填`method_artifact_id`。

仅练习/设计交接时固定教学与原task即可，不强建项目方法或run。进入combat/dance/vfx/voice正式实例时：先复用本项目适用且仍有效的已批准方法；没有则按原方法包整理`name/kind/method/limits/allowed_roles/tags`并计算摘要，运行`python3 -B scripts/knowledge/learning.py method validate FILE`。字段及含义见[方法与学习](../../../docs/design/memory-and-learning.md)，不把项目ID、来源对象或评测塞进可复用包，也不截去必要限制来凑长度。

沿原资源登记和真实决定取得方法产物UUID/产物SHA，professional-execution固定`method_artifact_id`及版本依赖，正式run再引用同一批准输入。已有明确正文的trial-method仍兼容；任意已批准说明文不能代替方法。将所读教学SHA、选用方法版本与适用差异记录在原task备注，不另建提示词权威。更新教材不静默改旧方法/实例/run；仅当前方法实质改变时追加受影响版本，沿原批准与依赖处理。该通用产物路径不代表PG的capability/pilot专用路线已迁移。

普通跑跳、潜行可按需用原镜头/状态或action、acting，不编二元combat；这些普通类型没有同一套专业必填与prompt检查，仍需实际核消费。真正攻防不能改标签绕约束，合法闪避可在contact相位写“未命中”。自我防护vfx的caster与target可同指一个真实实例的不同role；无施放者/目标的环境氛围先交场景/资产/编辑设计。专业route当前为generation/live/2d/3d/composite，纯剪辑交timeline。

现行`performance.prompt_fragment`保留完整规格文本，生成检查还核专业方法已固定入run、完整片段和所需素材确实进入最终请求；它不承诺自然语言条件可精确控制模型。mask/depth没有普通生成控制通道，分层说明不保证输出alpha；选合成/编辑路线需真实素材和执行工具。下一消费者逐项指出条件由什么承担，缺项返回原镜段，不能以字段非空或“后期再做”报告覆盖。

## 草拟、结构和示范各有什么用途

- 草拟：先写人物行动/信息或意象联系、声画和取舍；框架可只用“目标与保留项→当前表达→修改→理由与代价”，不要求每项三稿、反转或运镜。
- 教材：所属Skill references中的原创例子供比较，人物、服装、声线和情节都不是新作品默认值。换题时从真实输入重新定这些事实。
- 机器交接：`templates/*.json`保留原必填契约，详情见[模板使用](../../../templates/README.md)。现有模板包含演示身份/源SHA/声音，不能原样作正式输入。先映射正文和结构，再运行原contract validate；机器验证不能证明表达一致或审美成立。

映射时逐段核对：剧本正文的动作/对白/静默→screenplay单元及叙事引用→coverage覆盖→shot_plan入出点/必要资产→声音Cue→timeline固定媒体与实际区间。若正文有句子而结构缺失，先保留草稿并列差异，不丢正文或静默造来源；已批准快照不随教材修改。

## 有限比较与反馈

默认针对一个问题，在一个开发输入和一个未调参新输入上各做基线/改版，共4份结果、2对；事先固定唯一变量、保留项、每稿/总调用及停止条件。只报告本案例选择，不把它当普遍提升。无需比较的普通修改直接做，36+18稿属于专门扩展研究，不是每个作品必经步骤。

让实际负责人先描述看见/听见什么，再说明具体偏好、原话与时码，允许相等和无法判断。采用记录保存实际人数及失败，组合改动不能拆成每张卡效果。一个试点最多一次教材修订/开发复测，留出失败结束本次试点；不能无限换题到通过。

比较先选设计理解、同媒体剪辑或生成兑现的一层；4份结果不等于4次请求，额外素材、抽样及反馈修改均计原总上限，换模型或路线不重置。教学中故意写错的反例只检验理解，不能冒充真实基线或收益样本；真实旧稿必要的多处修复按组合报告。逐题给少量可观察判据，正常观看后再定位核查；遮挡看不清记证据不足，不从提示词推定结果，有意画外或延迟揭示按本题目标判断。

用户反馈绑定原版本/文字或时间位置，先解释要改善什么、哪些保留，再做最小修改并回到同一意见下展示差异。反馈修改追加版本，首次比较不回填；确定性字幕/剪辑不启动声画重生成。处理与不可用停点沿[审阅反馈](review-and-feedback.md)，最终接受/采用仍由实际用户决定。没有真实意见或媒体听审就保持未验。

## 工程可用与专业效果

读取、摘要、角色返回、安装资源及负例通过后，可以交付读取工具和候选教材；只有固定实际输出/审阅/新输入复验才支持对应效果声明。单项方法、组合、题材、阶段和模型的结论范围分别记录；不以卡片、规则、文件或测试数量评分。
