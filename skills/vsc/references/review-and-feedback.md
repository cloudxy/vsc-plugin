# 用户审阅与反馈

收到剧本、分镜、资产、声音、候选或成片的审阅与修改意见时读取。用户围绕当前作品审核、编辑、提出意见或要求重新生成；AI 负责定位对象、组织专业角色、管理必要中间记录和衔接下一步。文件数量、派单数量和阶段齐全不代表用户任务完成。

## 按用途判断成果 <a id="effective-result"></a>

派单前用原任务说明固定本轮问题、目标版本与范围、保留项、预期成果类型、实际消费者和检查办法；已有正文能表达时不加字段或另写交接表。草拟和探索先解决表达问题，正式交接前再集中检查。成果是否合格只针对本次用途和固定版本，不设跨阶段永久的“有效”标签。

| 事实 | 可以说明什么 | 还不能说明什么 |
| --- | --- | --- |
| 执行结束／已有候选 | 原任务、返回正文或已登记输出真实存在 | 下载、解码、用途与专业表现均通过 |
| 对本用途检查合格 | 所列版本满足已检查的内容与条件，未检项明确 | 用户已批准或已选择采用 |
| 已采用 | 有原权威记录的真实选择及适用范围 | 下游已经读到、编译或使用它 |
| 已消费 | 实际接收者读取并用于相应工作，能定位输入和使用处 | 后续成片或所有其他用途都已通过 |

这些事实沿原任务、检查、选择与用料关系表达，可以分别成立。技术成功但表演不符时同时保留执行成功与具体问题；合格而未采用的候选仍可比较。规格、提示词、Cue 和脚手架各有设计用途，但不能充当参考图、声音、视频或可播放成片。原素材缺失或工具不可用时如实保持未完成，受阻说明不能关闭原创作目标。

作品和可编辑成果、支撑选择的候选/试验、带依据的判断/修改决定、用于恢复的执行记录都可能有价值。探索在开始前写清问题、比较维度与资源边界；失败后在原尝试补观察及适用结论，保留未采用原因。不能事后给任意失败加一句“积累经验”就算成功，也不能为减少文件或提高通过率删掉失败样本、减少已授权探索或自动采用。

## 实际读取与交接检查 <a id="consumer-check"></a>

执行者和接收者按当前任务选用下表。它说明责任与用途，不要求新增阶段、审批、智能体或每阶段报告；多个消费者复用同一固定成果。

| 成果／生产责任 | 接收者实际读取并使用什么 | 缺项先返回哪里 |
| --- | --- | --- |
| 来源理解与改编／story-analyst、adaptation-editor | screenwriter 从出处核对关键人物、事件与取舍，分清事实和待核解释，再写具体场次 | 来源／改编对应段落 |
| 可拍剧本／screenwriter | director 读实际场次、行动、对白与静默，能据此安排人物行动和镜头覆盖 | 动机、因果或信息缺失回剧本／改编 |
| 镜头设计／director、continuity-supervisor | asset-director 和 generation-producer 用同一设计确定参考用途、动作、时长与相邻进出状态 | 调度、状态或覆盖回编导 |
| 资产规格与参考媒体／asset-director、generation-producer | generation-producer 打开所需图像/样音，核固定身份、变体、可见侧及用途，沿原输入绑定实际引用 | 缺参考、错身份／状态回资产 |
| 声音方案与音频／music-supervisor、声音执行者 | editor 试听固定音频及实际区间，将 Cue、对白/字幕和跨镜进出落到时间线 | 声源、表演或覆盖回声音责任环节 |
| 候选镜次／generation-producer | director/continuity-supervisor 审看动作与衔接；editor 读取实际媒体，检查可剪区间和必要声轨 | 缺字节先恢复；画面问题回相应制作／设计 |
| 样片与工程／editor、remotion-composer | post-reviewer 完整声画审看固定样片；需要编辑时实际打开含真实用料的工程 | 错用料、字幕、切点或混音回后期 |
| 成片及约定附件／交付责任人 | 用户或交付消费者播放、读取约定版本；核所见版本、交付规格与决定范围 | 缺附件回交付，内容问题回最早责任环节 |

1. **先读输入。** 执行者 consume 固定上下文后，打开任务必需的正文或媒体及适用方法；摘要只供导航。实际媒体未提供时不能以描述推断已观看、试听或可剪。
2. **返回真实结果。** 在原产物定位改动、保留项和未解决项，经原登记取得固定引用再 return。填写路径、完成宣言或自报“已检查”不代替登记、内容检查与实际审阅；不自签人工批准。
3. **在首次使用时核对。** 接收者按原权威核项目、版本/摘要、范围、用途、所需内容/字节及适用批准；读取通过后继续本职工作。用原读取、编译、任务输入或时间线用料事件定位消费处；只有收到引用而未使用时明确尚未消费。
4. **失败定位到对象。** 在原任务记录受影响版本、具体段落/镜头/时码、缺项、最早责任环节和可继续的独立范围。已有供应商输出但下载或登记失败先走原恢复；未知请求不重提。内容修订生成新版本并沿原依赖定位影响，不自动重做整集。
5. **复验变化部分。** 新版本或用途改变后重验适用项；旧基线晚到保留其来源，不覆盖新稿或套用新批准。同一问题没有新证据连续失败时遵守原重试/预算上限，返回可选处置，不无限抽样。

同题正反例见[可执行镜头](../../vsc-direct/references/blocking-coverage.md#usable-shot)、[规格与实际参考](../../vsc-assets/references/visual-attention-light.md#reference-delivery)、[修改说明与真实预览](../../vsc-post/references/sound-picture-rhythm.md#edit-result)。这些方法仍需在实际消费者中验证；规则落盘不能当作已提升质量或效率的证据。

## 呈现需要决定的内容

- 默认呈现当前可阅读、观看或试听的结果、本轮改动、尚待决定的问题及下一步。编辑、采用/通过、重新生成和反馈贴近被审内容；按实际可用动作显示，不要求用户在文件目录里寻找入口。
- 剧本按场次与对白阅读，分镜按画面与镜头观看，资产看外观/规格或样音，候选按同用途比较，成片按实际播放版本和时码审阅。用中文或可理解名称定位，不要求用户复制 ID、理解 JSON、提示词或运行包。
- 同阶段相关内容可以组成一个审阅包，明确所展示的版本、范围和必要依赖；一次真实决定沿既有接口记录各项适用决定，不按每个机器文件增加确认轮次。隐藏技术细节不能隐藏影响创作选择的变化、缺口或新增用量。
- 历史版本、未采用候选、实际请求和运行证据按需展开或查询。面向专家的查看、比较及导出入口仍保留；默认折叠不等于已删除或已减少实际落盘。

## 从意见到下一步

1. **固定上下文。** 从用户正在阅读/播放的项目、集、场、镜头、版本和时码定位目标；只取本次必需信息。区分对单个候选、本镜所有候选和全剧资产母版的意见，不把“这个”默认扩大到整个项目。
2. **理解目标与保留项。** 将原话转成要改善什么、改哪里、什么保持、怎样回看。推荐须基于已读取或实际观看/试听的内容；目标不明时先收敛对象或比较基准，不凭“感觉”编造用户偏好。只有不同解释会实质改变内容、范围或用量时，提出一个简短澄清；必要时分轮收敛。不让用户填写内部字段，也不因已有决定重复求确认。
3. **定位最早责任环节。** 文本与叙事回编剧/改编，摄影与动作调度回导演，身份/外观/参考回资产，声音表演回声音制作，字幕排版/剪辑回后期。只有必须重新生成的部分才进入生成；工程失败先恢复，不用新抽样代替恢复。
4. **形成最小改动。** 沿已有关系列受影响项、可复用项和实际缺口；需要时给简短差异或预览。有明确授权且前置满足的直接执行；创作批准、供应商用量及最终发布沿既有范围和入口，不把普通评论推定为批准，也不新增逐文件审批。
5. **执行并关联。** 使用现有草稿、批注/审阅、版本、局部制作和任务接口；专业派单固定最小输入。保存原话及其版本/范围关联、解释、实际操作和结果引用，优先归原对象历史，不为反馈另写一套说明文件或批准台账。现有接口不支持的动作如实报告缺口，不声称已经执行。
6. **带结果返回。** 展示改后的内容或同用途对比，说明落实了哪条意见、哪些部分保留、还有什么需用户决定。生成成功或任务结束不能自动将意见标为解决；以对应验收结果记录处理，需人判断的效果返回用户。刷新或接续从原权威恢复意见与结果，不重新猜进度。

批准始终绑定用户实际看到的固定版本、内容摘要与范围。用户审阅后内容发生变化时保留意见，重新呈现差异，不能将旧决定套到新内容；单镜采用不等于全片发布，意见、接受局部编辑与正式批准分别记录。此处不改变项目固定 Profile 或专业审片要求。

用户明确选择“修改后给我看”时，范围清晰、前置满足且已有授权覆盖的局部处理直接接续；授权内的正常用量不重复询问。仅记录意见的操作保留评论语义。故事、形象与声音、样片、成片可作为组织审阅的时机，按实际内容合并或再次出现，不新增固定次数的关卡，也不承诺固定几次点击即可完成。批量决定只包含用户看到并选定的固定项，逐项预检和返回结果，部分成功后仅恢复未完成项。

## 中间产物由系统管理

新增持久文件前先确定消费者、不可再生信息或恢复价值。编辑与意见保存在原工作副本/审阅历史，真实请求、候选、用量与恢复证据归原任务，派生预览优先引用或缓存；没有下游、审阅或恢复用途的说明不另存。必要的可编辑工程和明确交付仍保留，不强制每次同时输出 MD、JSON、HTML 三套原稿。

同一意图的重复提交、刷新、轮询和恢复沿原记录幂等处理；提交状态未知时先对账。用户明确“再生成一次”是新尝试，沿原上游创建新候选，不能因提示词相同吞掉。旧采用保留，候选数量按实际授权与用量控制，不把更少文件作为少做用户要求的理由。

先区分旧尝试、本轮新授权意图和本轮提交回执：相同操作键只恢复本轮同一意图；不能因重连再提交本轮未知请求，也不能把旧任务未知当作本轮已经提交。可独立识别、已授权且不依赖未知输出的新尝试不必天然等待旧任务结束；实际接口不支持时说明缺口，不绕过其前置，也不把新授权用于重复提交旧请求。

默认不展示、归档、可回收与删除是不同操作。正式引用、批准证据、来源和在途恢复依赖按原保留规则处理；不能仅因用户无需查看就删除。实际整理沿已有清单、引用核验和适用授权，不因本方法自动清理历史作品。

## 代表性检查

| 用户意见/操作 | 应得到的下一步 | 不合格信号 |
| --- | --- | --- |
| “这段对白太密，动作保留，改短再给我看” | 定位所指段落，提出/执行授权范围内的文本修订，回看差异 | 重写全剧、先要求用户找 JSON、直接批准新版 |
| “12 秒的字幕抬高一点，其他不动” | 固定播放版本和对应区间，调整字幕及必要合成；接口未接通则交接并保持待执行，回收实际预览后报告结果 | 重新生成整片、时码落到另一版、只转交就说已改好 |
| “这张脸可以，动作重来一次” | 固定身份与参考，创建新动作候选，按必要范围检查衔接 | 换角色母版、覆盖旧采用、把新抽样当重复请求 |
| “不是这个感觉”且无进一步上下文 | 基于当前结果提出推荐解释；有实质歧义时只澄清关键选择 | 直接全链重跑或向用户扔专业参数问卷 |
| 提交意见后刷新，原请求结果未知 | 恢复原意见及任务，对账后显示结果或可恢复问题 | 重复提交扣费，生成多份待审/审完说明 |
| 用户没有打开中间日志或历史候选 | 默认继续围绕当前作品审阅，证据仍可按需查询 | 将未查看当批准、将隐藏当减量或擅自删除引用 |

这些是执行与验收方法，不代表所有存储路线或界面已经具备统一反馈能力。判断完成须检查实际消费者、操作和固定版本结果。
