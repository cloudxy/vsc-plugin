# 组织生成请求与核首尾参考

这里给出VSC原创组织建议，不是词序权重、模型效果或受众偏好的试验结论。实际输入能力由当前本地适配器、模型登记与最终payload决定；方法不改变原批准、候选、用量、选择或Gate。

<a id="prompt-organization"></a>
## 五部分先组织，再接真实输入

| 部分 | 要回答的问题 | 回到原权威与消费者 |
| --- | --- | --- |
| 主体 | 哪个固定身份在做事、对谁或什么？ | 原资产／参与实例与本次真正传入的参考；不能只靠同名role辨人 |
| 动作 | 从什么状态开始，按何顺序改变，最后留下什么？ | 原scene-state与专业执行规格；完整固定片段保持，不另存可独立编辑的短摘要 |
| 镜头 | 哪个机位、范围或运动使关系可读？ | 原ShotPlan／camera；文字要求不冒充相机硬控制 |
| 光影 | 哪些光向和可见性须保持，何时改变？ | 原环境／参考及changes；先消除相互矛盾的要求 |
| 风格与声音 | 本镜为何采用这类画面和听觉关系？ | 已批准风格与声音方案；声音须进入真实支持的原生音画、音频或后期路线，prompt写到声音不等于已输出声音 |

图像已经提供的身份、服装与构图不用再堆同义形容词；保留必要身份锁定、道具数量、持物手、动态先后、接触、声音及不在图中的变化。五部分是漏项检查，不要求每次写五段，也不覆盖完整专业规格或state约束。现`prompt_fragment`保留全部专业参数，`compile_state_request`追加新显式状态；不得手动删掉固定片段后仍声称已被原guard覆盖。

原创例：首帧里A穿蓝外套、站在关闭的窗旁，右手握把手，主光从左来。目标只改变窗的开合。

- 初稿：“超清、精美、真实、非常细腻的蓝衣人，美丽夜景，华丽电影感，从右侧强光照来，迅速打开又关上窗，慢慢推出镜头，像首图一样固定构图。”
- 局部重写：“保持参考中A的身份、蓝外套、左侧主光和机位。A右手先转把手，再把窗推开到约定末态；停住并看窗外。固定中景，窗框和人物持续可见。雨声按已批准声音计划承担。”

差异是去掉重复修饰与光向／机位／动作矛盾，保留动态和锁定条件。没有比较媒体，不能宣布重写版更好看或更稳定。如果真实任务需要关窗、推镜或转光，应改原设计和参考，不用删形容词掩盖变更。

有效条件：输入图已足够明确，目标是一个可说明的变化。不适用：参考本身缺身份／空间，或核心要求只有时间顺序而没有可执行输入；先补规格、拆动作或换已支持路线。练习保持同一首图，只把目标改为“松开把手但不开窗”，重写动作并指出必须同步改变的末态与参考，不能沿用旧尾帧。

<a id="frame-pairing"></a>
## 先核参考，再选择模式

首尾帧逐项核同身份、服装道具、光向、空间参考系、机位与动词阶段。关闭→转把手→打开是一条可读的过程；若尾帧人已换手、窗把手反向或主光翻面，先返回参考与设计，不能要求模型自行解决矛盾。

入点约束足够且本地模式支持时用首帧；有明确末态且实际适配器支持时用首尾帧；身份／地点多参考则明确每张用途与真正请求顺序。硬首尾帧和参考模式的组合按当前适配器编译器核验，不因文档列出两种能力就假定能混用。相邻镜头能否共享边界帧仍按原bridge策略；反应镜或换机位不强行共享像素。

“核心主体先写”是组织建议；“前词必然权重更高”和“运动不得超过画宽1/4”在本任务没有受控证据，保持未验证经验，不能升为供应商中立硬规则或失败门。运动幅度应根据具体模型、任务、参考与可比试片检查。

<a id="negative-and-iteration"></a>
## 能力缺口与草稿迭代

当前两条本地VSC图像／视频适配路线没有接通独立negative_prompt字段，未知params受其allowlist校验。本VSC路线的该项控制尚不可用；这不代表供应商所有API都不支持。不要向正向prompt拼一串负面词并声称启用了负向控制；需要新能力时回适配器评估，按官方接口事实和最终payload接线，不能静默回退。

低质草稿只用于已经授权的构图或关系试探，先约定要确认什么、哪些细节不评。草稿仍是candidate，不是自动获选或方法实片评测；新抽样仍计原用量，恢复未知提交沿原回执，不通过反复草稿绕开预算。构图成立后按原选择／规格变更进入精修；失败回具体输入或动作，不以“再写更多提示词”替代诊断。

返回点：身份或光向冲突回资产／参考；动作先后不清回state／专业规格；编译器拒绝回真实能力；媒体未兑现回实际区间观察；风格偏好或采用决定沿原人审。本文没有创建新批准步骤。
