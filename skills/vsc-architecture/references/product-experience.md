# 产品与体验维护

在 VSC 面板、产物阅读、导航、表单或其他软件体验的审查、规划、实施中按需读取。沿 `vsc-architecture` 当前模式和授权范围工作；产品与设计是维护角色，不增加创作阶段、作品 Gate 或第二份项目状态。

## 职责与交接

- `product-manager` 明确谁在什么场景完成什么任务，区分用户报告、复现证据与假设，给出影响、范围、取舍和可观察验收。目标未被用户指定时提出有依据的建议，不编造负责人、用户研究或业务指标。
- `product-designer` 据任务定义信息层级、阅读与操作路径、状态反馈和视觉方案；将常态、长内容、窄屏、空态与失败恢复转成实现说明。影视美术仍走 `asset-director`。
- `orchestrator` 维持任务范围、编辑归属和交接；实现者依约修改，产品与设计角色分别按需求及体验证据复核。小修复可用短段落交接，不要求额外 PRD 或设计文档。

复杂任务适合派单时先通过 `context build` 固定最小包：目标与当前模式、指定界面/路由、必要输入与版本、验收任务、编辑所有权。沿既有 `consume → return` 绑定回收结果及记忆提议。实施者的自检不称为独立审查；独立首次审查用 `fresh`，复查用 `followup`，两者只读，且不携带本对象的旧通过结论作为判据。

## 从问题到实际界面

创作产品的默认路径沿[用户审阅与反馈](../../vsc/references/review-and-feedback.md)设计：以可阅读/播放的作品及审核、编辑、重新生成、反馈为操作中心。把意见解析、影响定位、局部执行与回看接通，不让用户管理机器文件；分别验收默认查阅负担、重复持久化和实际用量，不能用隐藏目录代替减量。

1. 从正常入口复现一项用户任务，记录到达目标的路径、受阻步骤和可见结果。优先解决找不到、读不清、无法继续、状态不明等阻碍；实现术语只在帮助用户决定时显示。
2. 将任务写成具体前后行为与验收操作，例如“打开长篇产物后能按正文层级连续阅读、跳转和回到列表”。确定本次最小范围及保留的界面约束，不把局部问题升级成整套品牌改造。
3. 设计主次信息和主要动作；导航先按用户任务明确归属，再按资料分组显示子项，避免将后端集合全部平铺或用统计条重复导航入口。核对当前任务、选中项与实际内容一致，各任务的浏览选择互不覆盖。阅读页采用符合内容的排版，技术元数据按查证需要披露。明确焦点与键盘行为、窄屏重排、长文本/链接溢出及加载、空态、失败后的继续路径。视觉选择服务于任务，沿已有字体、组件和样式系统复用。
4. 在真实运行入口走查受影响任务，按本次变化选取桌面/窄屏、长短内容、键盘及失败恢复；记录截图或操作证据、版本与未验证项。代码通过或静态截图不能证明操作可达，代理走查不能冒称真人用户研究。
5. 按原任务的可观察结果关闭问题；需求偏差退回产品，信息/交互偏差退回设计，渲染/事件/数据问题退回实现。仍需用户决定的创作、产品取舍沿原有入口呈现，不增加审批轮次。

## 角色方法与能力

以下方法用于软件体验维护。按任务选择相关职责；小改动可在同一份短交接中完成，不要求六个独立智能体、六份文档或新增审批。架构、开发、软件测试是本次维护任务的责任分工，不新增创作角色，也不将影视审片角色当作软件测试角色。能力成立需同时具备输入、做法、交付和退出证据；角色名称、方法文件或一次测试通过不证明后续任务已自动执行正确。

### UX-PM

**产品经理：把界面反馈转成可验收任务。** 适用于“混乱、难找、看不懂”等反馈及新功能入口设计。

- 输入：用户原话、真实入口、当前范围和观察到的行为；未知项单列。
- 做法：复现一次查找或操作 → 写清目标、受阻点与成功结果 → 确定本次取舍 → 给出一项正常操作及一项容易混淆的反例。按实际影响决定是否保留统计、入口或分组，不将某次删除上升为全站禁令。
- 交付：简短的“谁在什么入口完成什么任务、前后行为、范围、验收操作”。不得仅写“优化体验”，也不虚构调研、负责人或业务指标。

### UX-DESIGN

**产品设计师：将用户任务转成信息层级和交互状态。** 输入为 UX-PM 的任务与已有设计约束。

- 做法：列出任务、资料分组、内容及动作的归属 → 合并重复入口 → 定义选中、加载、空态、失败和返回行为 → 按影响补充键盘、放大或窄屏说明。需要层级时采用分组导航；简单页面保留适合它的结构，不强制所有页面套两级导航。
- 交付：可实现的入口与状态说明，能回答“现在在哪、正在看什么、下一步在哪里”。只调整配色、间距或复制一排按钮不能关闭信息归属问题。

### UX-ARCH

**架构责任：维护界面状态与数据权威的边界。** 输入为用户任务、交互方案及实际消费者。

- 做法：建立“任务 → 分组 → 集合/操作 → 权威来源”的对应 → 区分业务事实与浏览偏好 → 核对范围、关联实体、筛选、分页和固定版本如何切换 → 明确组件复用与任务差异。数据模型中的集合不直接决定产品导航；共享组件不要求共享全部入口。
- 交付：本次需要的状态关系、消费者和变更边界。例如进入任务直接读取目标集合，保留独立选择；切换范围时清理失效的关联或分页，防止迟到响应恢复旧内容。沿现有权威读写，不另建批准、记忆或项目状态。
- 可选样例：浏览偏好按用户、项目和任务隔离；恢复时依次考虑有效的显式入口、仍有效的偏好、任务默认值。请求携带递增标识，写入结果前核对当前任务、范围和标识，旧成功与旧错误均不得覆盖新视图。具体保存项、生命周期和固定版本规则沿实际接口确定，不要求增加状态框架或保存所有筛选条件。

### UX-IMPLEMENT

**实现责任：接通实际入口并保持行为一致。** 输入为任务、状态说明、现有接口及编辑归属。

- 做法：定位最终消费者 → 修改所属组件与接线 → 清理旧入口及无效样式 → 保持任务、选中项、请求范围和正文一致 → 验证异步响应、必要的焦点保留及失败后的继续操作。涉及配置或文件迁移时沿[架构执行检查](execution-checks.md#3-组织计划并消除重复)同步全部消费者。
- 交付：实际可运行的改动与相关回归证据。只有函数、截图、配置文件或孤立替身可用时，不能报告整条用户路径完成。

### UX-VERIFY

**软件验收责任：验证用户路径和证据边界。** 输入为验收操作、固定实现版本及可用运行入口。

- 做法：从正常入口完成任务 → 核对选择与内容 → 切换、返回并检查恢复 → 按影响检查空态、失败、键盘、长内容或窄屏 → 将未验证环境和缺口写清。自动化验证读取、并发和状态等适合确定性检查的行为；视觉与操作问题回到真实界面观察。
- 交付：操作、实际结果、证据、适用版本和未验范围。HTTP 成功、DOM 存在、测试数及桌面放大不分别等同于可用性通过、真人满意或手机/Safari 实测。自检明确标为自检，独立复核沿现有 fresh/followup 协议。

### UX-COORD

**编排者：让职责、交接与返工发生在实际任务中。** 输入为当前授权模式、已有结果、缺口和执行主体。

- 做法：确定需要哪些责任 → 为每项固定最小输入、输出和编辑归属 → 接通产品目标、设计、技术约束、实现与验收 → 按缺陷最早责任环节返工。角色未实际执行时如实记录，不把增加角色文件等同于完成角色参与；无独立执行者时按职责顺序处理并标明自检。
- 交付：本次责任与结果对应、证据及尚缺内容。用户只要求复盘或沉淀方法时，更新所指 Skill 与必要接线，不因此实施新的界面、数据库改造或整套计划。

## 代表性验收场景

按本次影响选择场景，不要求无关任务全量运行。使用合成输入或只读入口；场景中的“确认/批准”不能作为真实人工决定。

| 场景输入 | 应观察的处理 | 不合格信号 |
| --- | --- | --- |
| 某任务页面混排其他任务的资料和操作 | 先识别当前用户任务，再明确入口归属；按需显示分组和内容 | 只改颜色、继续平铺全部后端集合 |
| 共用组件承载两个不同任务 | 正文、请求及选中状态对应当前任务；有意义的浏览选择按任务隔离 | 顶部任务已变而正文/高亮仍留在另一任务；无意互相覆盖选择 |
| 切换范围、快速切换或旧请求迟到 | 清理失效状态，旧响应不恢复另一范围；失败后可继续 | 旧关联实体、分页或内容混入新范围；焦点无故丢失 |
| 已有工程测试通过，但只有桌面截图 | 补本次必要的真实操作，保留未验证环境说明 | 把截图或测试数量写成手机、真人或独立复核已通过 |
| “只梳理方案”，随后“继续” | 保留规划模式，输出归属、步骤与验收 | 自动修改产品或生产状态 |
| “把经验沉淀下来” | 抽象可复用方法，接入维护/角色入口，以隔离场景检查可执行性 | 只保存聊天结论，或借此重做产品、自动批准项目记忆 |

## 经验与证据的存放

- 通用做法以本参考文件为唯一正文，维护 Skill 和角色入口按职责读取；不在每个角色复制一份长期维护的规则。
- 具体案例、复现、版本、执行主体和验证范围留在本机维护台账/证据中，公开规则不复制作品、凭据或本机案例内容。
- 项目相关事实和个别角色经验继续沿既有角色记忆提案、来源与人工决定流程；维护 Skill 不等于创建或批准项目记忆，不把维护方法伪登记为已晋升的创作能力卡。记忆可引用方法 ID、适用条件和来源，方法正文保持单一来源。
- 方法改变后按受影响场景复核。明确区分“规则已持久化”“宿主入口已同步”“场景行为已观察”和“后续任务实际加载”；不能根据文件存在声称模型训练、全平台实时加载或今后永不出错。

## 使用固定版本上游方法

先运行 `python3 -B scripts/maintenance/vendor_skills.py --resolve architecture`，只读取相关 `guide` 返回的本机**上游原文**；缺失时明确未安装，不报告方法已加载。来源、完整 commit、许可证和用途以 [sources.lock.json](../../../vendor/sources.lock.json) 为准；不复制正文进核心，不执行候选脚本、bootstrap 或隐含网络动作。

| 来源与原文 | 使用时机与边界 |
| --- | --- |
| `anthropic-frontend-design/skills/frontend-design/SKILL.md` | 新建或重塑界面的视觉方向、文字与版式。现有任务与设计系统优先，不把示例品牌风格或确认步骤变成额外授权流程。 |
| `vercel-web-interface-guidelines/command.md` | 对本次界面做可访问性、焦点、内容、导航与响应式走查。直接使用锁定的原始规则；不执行 wrapper 中“每次抓取 main”路线，不静默更新规则。英文文案惯例只在本地语言与界面规范适用时采用。 |
| `agency-product-design/product/product-manager.md` | 用户问题、范围取舍与交接的方法参考。 |
| `agency-product-design/design/design-ui-designer.md`、`design/design-ux-researcher.md` | 信息与组件层级、研究问题和可用性任务的方法参考。 |

Agency 原文只是方法输入，不替换 VSC 身份、权限或记忆卡；不继承其虚构履历、整套组织编排、固定 KPI、默认全站主题或全生命周期任务。统计结论与用户偏好只能来自实际证据。新增上游文件先审查并显式路由，再进入任务。
