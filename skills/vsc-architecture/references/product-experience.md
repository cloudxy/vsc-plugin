# 产品与体验维护

在 VSC 面板、产物阅读、导航、表单或其他软件体验的审查、规划、实施中按需读取。沿 `vsc-architecture` 当前模式和授权范围工作；产品与设计是维护角色，不增加创作阶段、作品 Gate 或第二份项目状态。

## 职责与交接

- `product-manager` 明确谁在什么场景完成什么任务，区分用户报告、复现证据与假设，给出影响、范围、取舍和可观察验收。目标未被用户指定时提出有依据的建议，不编造负责人、用户研究或业务指标。
- `product-designer` 据任务定义信息层级、阅读与操作路径、状态反馈和视觉方案；将常态、长内容、窄屏、空态与失败恢复转成实现说明。影视美术仍走 `asset-director`。
- `orchestrator` 维持任务范围、编辑归属和交接；实现者依约修改，产品与设计角色分别按需求及体验证据复核。小修复可用短段落交接，不要求额外 PRD 或设计文档。
- `software-architect` 按需负责模块/接口、状态权威与恢复；`fullstack-engineer` 沿 [vsc-engineer](../../vsc-engineer/SKILL.md) 贯通实际用户路径；`database-engineer` 仅对本次数据影响沿 [vsc-database](../../vsc-database/SKILL.md) 负责约束、查询、事务与恢复，结构专项复用原 schema-review。单个文件只有一个编辑者，角色登记不使每次小修都增加串行门。

外部产品和截图只提供已看见的界面证据。记录观察入口、动作、可见状态与未进入范围，再抽取适用方法；看见项目/集卡片、工具分组或模式说明，不能推断其后台调度、存储、权限、实际生成能力或使用效果。没有进入或确认的路线保持未知，不照搬供应商绑定、强制弹窗或额外流程。

复杂任务适合派单时先通过 `context build` 固定最小包：目标与当前模式、指定界面/路由、必要输入与版本、验收任务、编辑所有权。沿既有 `consume → return` 绑定回收结果及记忆提议。实施者的自检不称为独立审查；独立首次审查用 `fresh`，复查用 `followup`，两者只读，且不携带本对象的旧通过结论作为判据。

## 从问题到实际界面

创作产品的默认路径沿[用户审阅与反馈](../../vsc/references/review-and-feedback.md)设计：以可阅读/播放的作品及审核、编辑、重新生成、反馈为操作中心。把意见解析、影响定位、局部执行与回看接通，不让用户管理机器文件；分别验收默认查阅负担、重复持久化和实际用量，不能用隐藏目录代替减量。

1. 从正常入口复现一项用户任务，记录到达目标的路径、受阻步骤和可见结果。优先解决找不到、读不清、无法继续、状态不明等阻碍；实现术语只在帮助用户决定时显示。
2. 将任务写成具体前后行为与验收操作，例如“打开长篇产物后能按正文层级连续阅读、跳转和回到列表”。确定本次最小范围及保留的界面约束，不把局部问题升级成整套品牌改造。
3. 设计主次信息和主要动作；导航先按用户任务明确归属，再按资料分组显示子项，避免将后端集合全部平铺或用统计条重复导航入口。核对当前任务、选中项与实际内容一致，各任务的浏览选择互不覆盖。阅读页采用符合内容的排版，技术元数据按查证需要披露。明确焦点与键盘行为、窄屏重排、长文本/链接溢出及加载、空态、失败后的继续路径。视觉选择服务于任务，沿已有字体、组件和样式系统复用。
4. 在真实运行入口走查受影响任务，按本次变化选取桌面/窄屏、长短内容、键盘及失败恢复；记录截图或操作证据、版本与未验证项。代码通过或静态截图不能证明操作可达，代理走查不能冒称真人用户研究。
5. 按原任务的可观察结果关闭问题；需求偏差退回产品，信息/交互偏差退回设计，渲染/事件/数据问题退回实现。仍需用户决定的创作、产品取舍沿原有入口呈现，不增加审批轮次。

## 角色方法与能力

以下方法用于软件体验维护。按任务选择相关职责；小改动可在同一份短交接中完成，不要求六个独立智能体、六份文档或新增审批。架构、开发、软件测试是本次维护任务的责任分工，使用已登记工程角色，不新增创作阶段，也不将影视审片角色当作软件测试角色。能力成立需同时具备输入、做法、交付和退出证据；角色名称、方法文件或一次测试通过不证明后续任务已自动执行正确。

### UX-PM

**产品经理：把界面反馈转成可验收任务。** 适用于“混乱、难找、看不懂”等反馈及新功能入口设计。

- 输入：用户原话、真实入口、当前范围和观察到的行为；未知项单列。
- 做法：复现一次查找或操作 → 写清目标、受阻点与成功结果 → 确定本次取舍 → 给出一项正常操作及一项容易混淆的反例。按实际影响决定是否保留统计、入口或分组，不将某次删除上升为全站禁令。
- 交付：简短的“谁在什么入口完成什么任务、前后行为、范围、验收操作”。不得仅写“优化体验”，也不虚构调研、负责人或业务指标。
- 对自动化产品，把人工步骤分为创作取舍、执行搬运与故障恢复。先消除抄编号、选择执行角色、另开命令、寻找返回结果等搬运；必要取舍仍由人决定。以同一任务的实际操作记录比较，不能只用按钮数或隐藏文件数判断改善。
- 专业工具的归属与排序按[创作顺序与可选步骤](#creative-tool-order)确定；验收用户能否从当前对象抵达所需工具、理解前置与返回结果，不能以每个工具都有独立页面为完成条件。

### UX-DESIGN

**产品设计师：将用户任务转成信息层级和交互状态。** 输入为 UX-PM 的任务与已有设计约束。

- 做法：列出任务、资料分组、内容及动作的归属 → 合并重复入口 → 定义选中、加载、空态、失败和返回行为 → 按影响补充键盘、放大或窄屏说明。需要层级时采用分组导航；简单页面保留适合它的结构，不强制所有页面套两级导航。
- 交付：可实现的入口与状态说明，能回答“现在在哪、正在看什么、下一步在哪里”。只调整配色、间距或复制一排按钮不能关闭信息归属问题。
- 让当前作品、本轮变化与意见保持可关联；长列表、正文与意见按各自阅读任务滚动。专业能力放在所属对象的编辑或更多操作中，窄屏改为可返回的单面板路径。迁移入口时逐项核去向，包含账户、初始化、失败恢复和专业工具，不能通过移除入口遗漏能力。
- 页头和对象工具按[紧凑布局与就近操作](#compact-object-tools)安排，在可读宽度内同行组织标题、范围与常用动作；窄屏可重排，不以强行一行、缩小字号或隐藏能力换空间。

### UX-ARCH

**软件架构师：维护界面状态与数据权威的边界。** 输入为用户任务、交互方案及实际消费者；完整方法沿 [vsc-architecture](../SKILL.md)，SQL/迁移责任交原数据库专项。

- 做法：建立“任务 → 分组 → 集合/操作 → 权威来源”的对应 → 区分业务事实与浏览偏好 → 核对范围、关联实体、筛选、分页和固定版本如何切换 → 明确组件复用与任务差异。数据模型中的集合不直接决定产品导航；共享组件不要求共享全部入口。
- 交付：本次需要的状态关系、消费者和变更边界。例如进入任务直接读取目标集合，保留独立选择；切换范围时清理失效的关联或分页，防止迟到响应恢复旧内容。沿现有权威读写，不另建批准、记忆或项目状态。
- 自动接续必须找到实际领取、执行、心跳、产物登记和结果读回的消费者。先交付一条完整的小路径，再扩专业类型；记录“已派单、已执行、有结果、已采用”的区别。已有输出但原上下文失效时保全回执，不重扣费、不强行覆盖新版本。
- 按[成果的权威与真实引用](#result-authority)核一份成果怎样被多个界面和专业消费者使用；类型、用料和存储事实不能从 UI 卡片数量推断，不为展示方便另造完成状态。
- 可选样例：浏览偏好按用户、项目和任务隔离；恢复时依次考虑有效的显式入口、仍有效的偏好、任务默认值。请求携带递增标识，写入结果前核对当前任务、范围和标识，旧成功与旧错误均不得覆盖新视图。具体保存项、生命周期和固定版本规则沿实际接口确定，不要求增加状态框架或保存所有筛选条件。

### UX-IMPLEMENT

**全栈工程师：接通实际入口并保持行为一致。** 输入为任务、状态说明、现有接口及编辑归属；实施方法与跨层交接沿 [vsc-engineer](../../vsc-engineer/SKILL.md)。

- 做法：定位最终消费者 → 修改所属组件与接线 → 清理旧入口及无效样式 → 保持任务、选中项、请求范围和正文一致 → 验证异步响应、必要的焦点保留及失败后的继续操作。涉及配置或文件迁移时沿[架构执行检查](execution-checks.md#3-组织计划并消除重复)同步全部消费者。
- 交付：实际可运行的改动与相关回归证据。只有函数、截图、配置文件或孤立替身可用时，不能报告整条用户路径完成。

### UX-VERIFY

**软件验收责任：验证用户路径和证据边界。** 输入为验收操作、固定实现版本及可用运行入口。

- 做法：从正常入口完成任务 → 核对选择与内容 → 切换、返回并检查恢复 → 按影响检查空态、失败、键盘、长内容或窄屏 → 将未验证环境和缺口写清。自动化验证读取、并发和状态等适合确定性检查的行为；视觉与操作问题回到真实界面观察。
- 交付：操作、实际结果、证据、适用版本和未验范围。HTTP 成功、DOM 存在、测试数及桌面放大不分别等同于可用性通过、真人满意或手机/Safari 实测。自检明确标为自检，独立复核沿现有 fresh/followup 协议。

### UX-COORD

**编排者：让职责、交接与返工发生在实际任务中。** 输入为当前授权模式、已有结果、缺口和执行主体。

- 做法：确定需要哪些责任 → 为每项固定最小输入、输出和编辑归属 → 接通产品目标、设计、技术约束、实现与验收 → 按缺陷最早责任环节返工。角色未实际执行时如实记录，不把增加角色文件等同于完成角色参与；无独立执行者时按职责顺序处理并标明自检。
- 交付：本次责任与结果对应、证据及尚缺内容。用户只要求复盘或沉淀方法时，更新所指 Skill 与必要接线，不因此实施新的界面、数据库改造或整套计划。

## 创作顺序与可选步骤 <a id="creative-tool-order"></a>

产品经理先画出当前任务的“对象 → 要做的事 → 输入/成果 → 下一消费者”，按现有创作依赖分组专业工具。项目、集、场、镜头承担不同范围；在集卡上的操作应保留集范围，镜头工具靠近镜头，资源设置留在适用的全局入口。侧导航用于稳定定位，页面内工具用于当前对象；这是分工方法，不要求所有界面复制同一侧栏或卡片样式。

专业路线按创作顺序解释，例如资产/参考准备、镜头设计、视频候选与后期处理；既有 Profile 和前置决定真实顺序，界面分组不成为新的 Gate。站位图、分镜图、画布或其他辅助步骤在确有用途时说明“解决什么、需要什么、产出供谁用、何时可以略过”。用户已经有合适输入时直接继续，不为凑齐流程强制补图或弹出模式选择。

**原创同题对比。** 任务是“打开第二集，为选中的第五镜继续制作”。无效方案把资产、分镜、视频、导出、账号全部平铺，点击视频还要求重新选择项目/集。可交接方案让第二集保留选择，在第五镜旁呈现所需的参考/设计/候选入口；若缺参考，显示具体缺项并返回该对象，已有输入时直接接续。产品交给设计的是入口归属和这两种条件的验收操作，工具数量本身不算收益。

## 紧凑布局与就近操作 <a id="compact-object-tools"></a>

设计师先合并重复的页头、说明和状态条，把当前标题/范围与常用工具放在同一视觉区域；宽度允许时同行，次要工具按用途收进可发现的更多操作。工具贴近被操作的正文、镜头或卡片，点击后保持对象/版本，并能回到结果。对当前创作有意义的提示和失败原因仍保留，不能为紧凑而隐藏缺项。

**同题设计对比。** 对上述第二集第五镜，无效方案给标题、副标题、统计、范围、工具各占一整行，内容被挤到下方；或反过来把所有控件压成无标签小图标。可交接方案在桌面以一行标题/范围/主要动作组织页头，镜头卡就近放当前动作；窄屏和200%放大时允许分行或转为单面板，长标题可换行，按钮文字、焦点、触控和返回路径仍可用。固定导航或工具条不得遮盖内容与焦点。

验收从实际入口选中目标、触发一次适用操作、回看结果，再以长中文标题、390px宽度、200%放大及键盘检查；记录实际运行环境。只有截图时可判断该截图的层级与间距，不能声称操作、响应式或真人体验已验证。不以页头像素数或按钮减少量单独认定改善。

## 成果的权威与真实引用 <a id="result-authority"></a>

架构责任为同一任务标明事实归属：现有项目/版本、任务输入输出、检查、采用与实际用料关系分别沿原权威；面板按这些关系投影可读内容。多个入口共享固定引用和所属领域检查，不各自保存“已完成”布尔值，不将摘要或预览缓存升级为第二份原稿。实际媒体有原登记和可消费字节，规格与提示词按设计类型显示；没有媒体时给具体缺项与原恢复入口。

**同题架构对比。** 无效方案为“第五镜制作完成”在任务、卡片和额外交接 JSON 各写一份状态，附三份说明却没有候选视频。可交接方案保留原任务回执及固定候选，卡片从同一事实显示“已有结果，待审”或实际缺项；生成输入、剪辑用料引用对应版本，消费事件可定位。若已有视频只差转存，恢复原请求；若只有设计，按设计成果呈现。任务执行、用途检查、采用与消费的区别沿[成果口径](../../vsc/references/review-and-feedback.md#effective-result)，不另建一套权威。

检查从界面结果追到固定记录与字节，再从下游输入/时间线反向核所用版本；刷新、切换范围和旧响应晚到不得串用。需要索引或缓存时先列消费者和失效条件；持久说明只为不可再生信息、审阅或恢复而建，不用多写文档、文件减量或静态卡片冒充成果。外部界面布局不提供其后端采用了这套方法的证据。

## 代表性验收场景

按本次影响选择场景，不要求无关任务全量运行。使用合成输入或只读入口；场景中的“确认/批准”不能作为真实人工决定。

| 场景输入 | 应观察的处理 | 不合格信号 |
| --- | --- | --- |
| 某任务页面混排其他任务的资料和操作 | 先识别当前用户任务，再明确入口归属；按需显示分组和内容 | 只改颜色、继续平铺全部后端集合 |
| 共用组件承载两个不同任务 | 正文、请求及选中状态对应当前任务；有意义的浏览选择按任务隔离 | 顶部任务已变而正文/高亮仍留在另一任务；无意互相覆盖选择 |
| 切换范围、快速切换或旧请求迟到 | 清理失效状态，旧响应不恢复另一范围；失败后可继续 | 旧关联实体、分页或内容混入新范围；焦点无故丢失 |
| 已有工程测试通过，但只有桌面截图 | 补本次必要的真实操作，保留未验证环境说明 | 把截图或测试数量写成手机、真人或独立复核已通过 |
| “只梳理方案”，随后“继续” | 保留规划模式，输出归属、步骤与验收 | 自动修改产品或生产状态 |
| “把经验沉淀下来” | 抽象可复用方法，接入维护/角色入口，以隔离场景检查可执行性 | 只保存聊天结论，或借此重做产品、自动批准项目记忆 |
| 当前对象已有输入，辅助站位图可选 | 工具按创作顺序分组，就近操作并保留对象；说明辅助步骤用途，可直接继续已具备前置的任务 | 强制补齐每个工具、重选项目/集或增加模式确认 |
| 页头过高且常用动作远离内容 | 合并重复信息、宽屏同行，窄屏/放大可读可操作；内容及焦点不被遮盖 | 只删提示、缩小文字、隐藏能力或强塞一行 |
